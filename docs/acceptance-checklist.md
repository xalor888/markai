# 验收清单（照着点一遍）

> 目的：不用读代码，5–10 分钟确认「这次升级真的能用」。
> 每项都写明了**看到什么算通过**。任何一项不符，把那一节的名字告诉我。

## 准备

1. 打开 `chrome://extensions` → 开发者模式 → 「加载已解压的扩展程序」→ 选 `output/chrome-mv3`
   （先跑一次 `npm run build`）。
2. 确认扩展 ID 是 `ojlfhclcoecgjbgklcbcfbjjjlhjhd`（固定 ID，换目录也不会丢配置）。
3. 点扩展图标 → 「打开完整管理页」。

## A. 自动整理（核心）

| # | 做什么 | 看到什么算通过 |
| --- | --- | --- |
| A1 | 随便收藏一个网页（Ctrl+D） | **约 0.2 秒内**它自己归位；底部弹一条提示告诉你去了哪里 |
| A2 | 点顶栏「整理」（带小圆点表示有新的） | 面板打开：今天 N 条 / 累计 N 条 / 失败 N 条；下面一行「判断来源：本地规则 N · 模型 N · 兜底 N」 |
| A3 | 看那条记录 | 显示「域名 → 去向」，例如 `github.com → 自动整理 / github.com` |
| A4 | 点那条记录的「↶」 | 书签回到原位置；**该站点自动进入「已停用自动整理」名单**（面板底部能看到） |
| A5 | 再收藏一次那个站点 | 不再自动搬（这是刻意的） |
| A6 | 面板底部点那个站点的 × | 恢复后，新收藏会重新参与自动整理 |

## B. 补整理

| # | 做什么 | 看到什么算通过 |
| --- | --- | --- |
| B1 | 在根目录手动放几条书签（或找一个散落的） | 「补整理已有书签」旁显示「检测到 N 条散落在根目录」 |
| B2 | 点「开始」 | 出现进度「正在处理 x/y · 已归入 z · 还需约…」，可随时「取消」 |

| B4 | 让几条失败（断网或填错 API Key） | 出现红色的失败记录，可单独「↻」重试；两条以上会出现「重试全部 N」 |

## E. 安全边界（这些"不做"是对的）

| # | 做什么 | 看到什么算通过 |
| --- | --- | --- |
| E1 | 撤回过删除的轮次后点「撤销全部」 | 会**停在**那一步，并告诉你「还有 M 步当前无法撤销（含删除的操作不支持回退）」 |
| E2 | 补整理了 20 条后想看能不能一次全退 | 不能——每条一个撤销点、最多保留 10 个。这是**可靠性优先**的选择 |
| E3 | 把文件夹拖进它自己 | 移动对话框里它自己是**禁用**的，且写明原因 |

## 附：哪些已自动化，哪些要你亲眼看

清单里绝大多数项都有 **e2e（96 项）或单测（637 项）**守着——自动化挂了我会先知道。
下面这几项**没有完整的自动化覆盖**，改动时最需要你亲眼看一眼：

| 项 | 覆盖情况 |
| --- | --- |
| E3 移到自己/子文件夹 | **逻辑有单测**（`isSelfOrDescendant` 两条），但「选择器里禁用 + 文案」只有目测 |
| 子项加载失败的错误态 | catch 分支，难以稳定触发（不存在的 id 在部分 Chrome 版本返回空数组而非拒绝） |
| `<all_urls>` 权限 | 刻意保留（兼容自定义 Base URL），非缺陷 |

其余如「toast 位置」「空状态出口」「树里的条数」「提示条出现与消失」「补整理进度恢复」
「选中 >100 条时的站内确认框」都已写成断言，不需要手工验。
