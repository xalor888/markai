### 第 3 批（D4 无障碍）— 2026-11-02

**6. 新增无障碍守卫，并修掉它抓到的焦点环缺失**（commit `90c54cc`）

- 守卫一：页面上每个 `button` 必须有可访问名称（文字 / aria-label / title）。
  当前 23 个按钮，0 个无名称——这条防的是"以后再加图标按钮忘了写标签"。
- 守卫二：键盘聚焦时焦点必须可见（outline 或 box-shadow 非 none）。
- **守卫立刻抓到真问题**：搜索框 `outline-none` + 只改边框颜色，
  实测 `getComputedStyle` 里 outline 与 box-shadow **都是 none**，
  键盘用户完全看不出焦点在哪。项目里排序下拉、树过滤都有 `ring-1`，只有它漏了。
- 证据：修前 FAIL（`{"outline":"none","shadow":"none"}`）→ 修后 PASS。

**状态**：tsc ✅ / 单测 720 ✅ / build ✅ / e2e **27/27 · 14.9s**

### 第 1 批（D1 稳定性）— 2026-11-01

**1. `loadTree` 并发刷新被静默丢弃**（commit `803f0c0`）

- 缺陷：`if (get().loading) return;` —— 加载期间到来的刷新被丢掉，界面停在旧数据上。
  触发路径：刷新按钮、AI mutating tool 事件、书签变更事件（300ms 去抖后）。
  大库上 getTree 要几百毫秒，撞窗口概率不低，表现是"点了没反应 / 新书签不出现"。
- 修法：合并（coalescing）。加载中记一个布尔标记，`finally` 里补跑一次；
  5 次连点合并成 1 次，失败路径也补跑。
- 证据：T106 三条 + **证伪**（撤回修复 → 「补跑」立刻转红，装回 → 720 全绿）。

**当前状态**：tsc ✅ / 单测 **720** / build ✅ / e2e **25/25 · 14.1s / 视觉 15/15（且真实）**
