# v0.2.102 — 以后新增一条诊断，必须先证明它触发得了

## 起点

上一轮（0.2.101）抓到两条「用户永远看不到」的诊断，根因都是
**「存储 → 快照」这一层断掉**：`readSnapshot` 传错了形状，`diagnose` 拿到的永远是空。

当时补的契约测试是「点了修复，问题必须消失」。但它有个漏洞：
**它只覆盖我想到的那几个诊断。**

## 做了什么

把契约倒过来钉：

```
从 diagnostics.ts 源码里抽出全部诊断 id
  → 每一个都必须在表里有触发种子
  → 摆了种子必须真的触发
```

于是**新增诊断却忘了验证可达性，测试直接红**。

当前覆盖 16 条诊断，全部可达。

## 顺带补上「存储 → 快照」这一层

`ai.last-error` 这条诊断看的是 `snapshot.lastAiError`，而它是 `readSnapshot` 里的
`lastAiErrorOf` 从整理记录里抽出来的——**正是上一轮出事的那一层**。

所以单独加了一条走真实读取路径的用例：

```
整理记录里有一条 action:'failed' → readSnapshot() → lastAiError 有值 → 报得出 ai.last-error
```

## 验证

两次证伪：

1. 把 `lastAiErrorOf` 的字段名从 `action/detail` 改成 `status/message`
   → `lastAiError` 变 null，生产路径用例立刻红
2. 往 `diagnostics.ts` 加一条永远触发不了的死诊断
   → 「这些诊断没有可达性种子」立刻红

## 过程中正则错了一次

第一版正则要求 `id: '...'` 在**行尾**，我加的证伪用例是单行写法，没被抽到，
证伪静默通过。放松成「行首 + 尾逗号」并用**真实的多行风格**重证，才抓到。

> 又是那条老规矩：**证伪没红，先怀疑证伪本身。**
