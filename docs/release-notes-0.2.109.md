# v0.2.109 — 按钮说「还原 4 项」，toast 说「已还原 1 项」

## 缺陷

「会还原多少条书签」这个数字，**两处用了不同单位**：

| 位置 | 数的是什么 |
|---|---|
| 按钮角标 / 「还原 N 项」 | `undoReadiness().count` —— **书签条数**（批次按条数、删除按子树节点数） |
| 撤销后的 toast | `applyUndo().restored` —— **操作条数** |

于是删掉一个含 3 个子书签的文件夹时：

- 按钮说 **「还原 4 项」**（文件夹 1 + 子书签 3）
- 点完 toast 说 **「已还原 1 项」**（一次删除操作）

**用户以为只还原了一部分。**

## 修法

`restored` 改成累加 `opWeight(op)`——和 `undoReadiness().count` 同一单位。
另加 `restoredOps` 保留操作条数（失败明细按操作计，用这个）。

toast 文案也跟着说清楚：

```
已还原 4 项书签，1 个操作失败
```

两个数的单位不同，混在一句话里必须写明，否则用户会以为总数对不上。

## 验证

```
PASS  撤销结果报的条数与按钮承诺的条数同单位（书签条数）
```

**证伪**：把 `restored` 改回数操作条数 → 失败信息正是用户会看到的那个矛盾：

```
撤销结果报的条数必须与按钮承诺的一致：按钮 4，结果 1
```
