# v0.2.110 — AI 跟你说的「两年没访问」，数的不是那个

## 缺陷

`stats` 工具返回的字段叫 **`超过两年未访问`**。

但判据是：

```ts
if (lastUsed <= 0 && added > 0 && now - added > TWO_YEARS) unusedTwoYears++;
```

也就是「**从未打开**且添加超过两年」。

区别很实际：Chrome 的 `dateLastUsed` 只在书签被打开过时才写。
「三年前打开过一次」的书签 `dateLastUsed` 有值，**这个判据不算它**。

于是 AI 会说「你有 800 条两年没访问了」，实际数的是「从未打开且够旧」的条数。
**你据此决定清理，范围是错的。**

## 修法

字段改名，让名字说清判据：

```
超过两年未访问  →  从未打开且添加超过两年
```

判据本身不动——它是个合理的保守启发式，只是名字骗了人。

## 顺带：这些字段此前一条断言都没有

`stats` 只测过 `书签总数` / `文件夹总数`。
`空文件夹数`、这个陈旧数、`根目录分布` **全是裸奔**。

补了一条，五个字段全验。因为 store 是跨用例累积的模块级数组，
用**增量**断言（先取基线 → 造数据 → 再取一次）。

## 验证

**证伪**：把字段名改回 `超过两年未访问` →

```
字段名必须说清判据是「从未打开」，实际键：
["书签总数","文件夹总数","空文件夹数","超过两年未访问","根目录分布"]
```
