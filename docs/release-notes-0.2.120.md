# v0.2.120 — Ctrl+A 说「全选」，其实只选到 100 条

## 缺陷

搜索结果显示上限是 100 条（`setSearchResults(r.slice(0, 100))`），
界面也如实显示「· 100+ 条」。

但 **Ctrl+A 选的是当前显示的列表**——最多 100 条，而且**没有任何提示**。

于是：

1. 你搜一个常见词，出来 250 条匹配
2. 按 Ctrl+A，状态栏显示「已选 100 项」
3. 你以为把全部匹配都选了，点删除/移动
4. **另外 150 条原封不动**

头部写着「100+ 条」、脚部写着「已选 100 项」——两个数字对得上，但**没有任何一句告诉你"还有没选到的"**。

## 修法

搜索模式下 Ctrl+A 且结果触达上限时，补一句：

```
已选 100 项
搜索结果显示上限为 100 条，可能还有更多匹配项未被选中。
可缩小关键词或到文件夹里全选。
```

浏览模式不弹——那是在制造噪音。

（代码里本来就有同立场的前例：`openSelected` 超 25 条时提示「结果过多，仅打开前 25 个（共 N 个）」。Ctrl+A 这条一直忘了。）

## 验证

e2e 新增 **3 项**：

```
PASS 浏览模式 Ctrl+A 不弹"结果有上限"提示（不制造噪音）
PASS 前置：搜索结果确实触达 100 条上限        · {"capped":"· 100+ 条"}
PASS 搜索模式 Ctrl+A 提示"可能还有更多匹配项未被选中"
```

**证伪**：把提示条件改成 `false` →

```
FAIL 搜索模式 Ctrl+A 提示"可能还有更多匹配项未被选中" · {"searchToast":0}
```
