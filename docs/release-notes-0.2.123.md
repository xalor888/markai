# v0.2.123 — 你说过「这个站点别动」，第 101 次之后它忘了

## 缺陷

「站点免打扰」名单记的是用户在整理记录里点「↶ 撤销」时说的话——
**「这个站点这么归类，我不认」**。

模块文档写的规则是无条件的：

> 撤销某次自动整理 → 该注册域进入名单，**之后新书签不再自动整理**

但名单有 100 条上限，且第 101 个加入时**静默挤出最旧一条**：

```ts
const next = [{ domain: target, at: now }, ...list.filter(...)].slice(0, ORGANIZE_OPTOUT_LIMIT);
```

于是重度用户撤销 100 次之后：

- 最早那条指令**悄悄失效**
- 那个站点又会被自动搬
- **而用户以为自己的话一直算数**

注释里写着「用户可能撤销很多次，但没必要无限增长」——把存储顾虑凌驾于用户明确指令之上。

这是 0.2.122 同一类缺陷的又一例：**有上界的列表静默丢东西**。上轮是撤销守卫，这轮是用户亲口说的话。

## 修法

两件事：

**1. 上限 100 → 1000**

1000 条 × 约 60 字节 ≈ 60 KB，相对 10 MB 配额可忽略；而现实中一个用户撤销过的注册域数量远到不了这个量级，所以它实际上不可达，同时仍给存储留一道硬边界。

**2. 万一真撞上，必须说出来**

`addOptOutDomain` 现在返回被挤掉的那条，调用方据此告知用户：

```
免打扰名单已满（1000 个站点），「site0.example.com」的免打扰已失效，
将被重新自动整理。可在整理记录里清空名单后重新设置。
```

**静默丢弃一条用户明确的要求，比不记更糟。**

## 验证

更新了既有的上限用例（它原本把「100 条静默挤出」当成正确行为钉住），并新增：

```
PASS 免打扰名单有硬上界，且挤出时必须把那条回给调用方（不静默丢用户指令）
PASS 未撞上上限时不回传 evicted（不制造噪音）
```

**证伪**：把 `return evicted ? { evicted } : {}` 改成 `return {}` →

```
撞上上限必须回传被挤掉的那条，实际 {}
```
