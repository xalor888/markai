# v0.2.125 — 你粘了 2000 条书签，它说「我都看过了」

## 缺陷

`selectHistory` 里单条消息超 6000 字符会被 `slice`，然后静默换成一个截断文本的新消息对象——
**没有任何标记**。模型看到一条半句话戛然而止的消息，却不知道它被切过。

最常见的场景：你粘一份几百条的书签清单（远超 6000 字符），模型只读到前 6000 字符，
然后自信地说「我已看过你列的 2000 条」。**你完全有理由相信它看全了——那是你刚发出去的消息。**

## 修到一半发现真正的祸根

先给 `selectHistory` 加了标记。测试还是红——发出去的内容正好 6000 字符，标记不见了。

一路查到 `runAgentTurn` 里还有**第二次切片**：

```ts
for (const m of apiHistory) {
  const content = extractText(m).slice(0, MAX_MESSAGE_CHARS);   // ← 就是这行
  apiMessages.push({ role: m.role, content: content || null });
}
```

`selectHistory` 早就把每条消息收窄到 6000 以内了，所以这行对普通消息是**空操作**——
它**唯一**的实际作用，就是把刚追加的「内容被截断」标记切掉（标记接在 6000 字符之后）。

**加了多少层防护，下一行就给你抹掉多少。**

## 修法

1. `selectHistory`：截断时追加标记，写清原长与实际发送长度
   ```
   […该消息原有 61782 字符，此处因上下文限制只发送了前 6000 字符，内容被截断]
   ```
2. 移除 `runAgentTurn` 里那行冗余切片，并注释说明它为什么有害
