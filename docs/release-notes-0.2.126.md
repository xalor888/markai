# v0.2.126 — 你指着刚发的话提问，它只读过前 8000 字

## 缺陷

`runAgentTurn` 里当前这条用户消息：

```ts
apiMessages.push({ role: 'user', content: text.slice(0, 8000) });
```

**静默截断。**

而聊天界面显示的是**完整**消息——它存在 store 里、原样渲染。

于是：

- 你当场粘一份 30000 字符的书签清单
- 界面上你看到自己发出去的**完整**内容
- 模型只读过前 8000 字符
- 你指着第 500 条问「这条该放哪」，它根本没见过那条

**「你看到的」和「模型看到的」静默不一致。** 这比历史消息被截更糟——
那是你刚打出来、此刻正显示在屏幕上的话。

（0.2.125 修的是历史里的单条消息；漏了当前这条，而它才是最常粘长内容的地方。）

## 修法

截断时追加标记，并指引补救：

```
[…你发送的这条消息原有 30000 字符，此处因长度限制只发送了前 8000 字符，
内容被截断。如你的问题依赖被截掉的部分，请把相关内容缩短后重新发送。]
```

短消息一个字符都不改（反向也测）。

## 验证

```
PASS 当前消息被截断时明确标记（用户看到的和模型看到的不能静默不一致）
```

1200 条 × 25 字符 ≈ 30000。验：带标记、说清原长、说清实际发送长度、
指引「缩短后重新发送」；反向验短消息**逐字原样**。

**证伪**：改回 `text.slice(0, MAX_TEXT_CHARS)` →

```

```
