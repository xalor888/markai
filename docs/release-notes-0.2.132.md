# v0.2.132 — 「无中间服务器」——可你刚让我填了中转地址

## 缺陷

设置页的「安全机制」一节无条件写着：

> API Key 仅存于浏览器本地，不同步到云端；请求由后台直发所选服务商，**无中间服务器**。

但**同一个设置页上**：

- 有一个预设直接叫「自定义（OpenAI 兼容）」，文档原话是「自定义端点（**中转站/代理**）通常也需要 Key」
- Base URL 字段完全可填，placeholder 就是 `api.example.com/v1`

于是你真去配了中转，这句话就是假的——**而它出现在「安全机制」这个最不该说错话的地方**。

其余两条承诺核对过，是真的：
- 「API Key 仅存于浏览器本地，不同步到云端」✅
- 「删除默认需你确认」✅（默认走 `propose_deletions` 提议，有明确的「无需确认」开关）

## 修法

改成如实表述，并说清边界：

> API Key 仅存于浏览器本地，不同步到云端；请求由后台直接发向你填的 Base URL。
>
> 内置预设（OpenAI / DeepSeek / Moonshot / 智谱 / Ollama / OpenCode）都是服务商官方地址。
> 若你选了「自定义」并填了自己的 Base URL，请求就会经过**那个**地址——
> 它是不是中转、由谁运营，只有你自己知道，请只填你信任的端点。

## 验证

新增 3 项 e2e 契约守卫：

```
PASS 设置页有「安全机制」这一节
PASS 安全说明不再无条件声称「无中间服务器」
PASS 安全说明如实说明自定义 Base URL 会经过那个地址
```

**证伪**：把措辞改回「无中间服务器」→ 第二条转红。

## 过程中挖出一个测试自身的转义 bug

断言一直莫名转红。逐层查下去——`codes` 打出 `[66,97,115,101,32,85,82,76]`（`B a s e ␠ U R L`），
**DOM 里的文本完好无损**。问题在表达式本身：

```js
const optEv = (expr) => cdp.send('Runtime.evaluate', { expression: expr })
// 调用处是模板字面量：
optEv(`(() => { ... raw.replace(/\s+/g, ' ') ... })()`)
```

**模板字面量里 `\s` 不是合法转义，反斜杠会被丢掉。** 发给浏览器的表达式实际是：

```js
raw.replace(/s+/g, ' ')     // ← 把字母 s 全换成空格！
```

症状：`Base URL` → `Ba e URL`、`Moonshot` → `Moon hot`。而断言正好在查 `Base URL`。

e2e 里**另有一处**（弹出窗的 `organizeText`）踩着同一个坑——它的两条断言只查 `.length > 0`
和 `.includes('2')`，所以一直没红，但显示文本被污染了很久。两处都改成 `\\s`。
