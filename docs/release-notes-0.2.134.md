# v0.2.134 — 一条名叫「任务链路走通」的测试，函数体是 `() => true`

## 缺陷一：汇总用例从来没验证过任何东西

```js
ok('任务链路走通（导出→分类→检测→提议）', () => true);
```

名字承诺整条链路走通，函数体是**恒真**。而它要汇总的那一步——`propose_deletions`——
嵌在两层 `if` 里：

```js
const target = cj.items.find((i) => i.type === 'deep');
if (target) {
  ...
  if (hit) {
    ok('propose_deletions 提交删除提议', () => assert.equal(pj.submitted, 1));
  }
}
```

夹具里没有 `deep` 类型、或搜索没命中时，那一步**静默不跑**，而汇总用例照样绿。

**整条链路从没被真正验证过。**

## 缺陷二：两个断言的失败会吞掉整个套件

```js
await assert.rejects(() => memMod.addMemoryItem('   '), /不能为空/);
ok('addMemoryItem：空内容拒绝', () => {});      // ← 恒真的占位
```

真断言挂在块级顶层。它一旦失败会**抛穿整个 IIFE**——后面八百多项一起被吞，
只留下一条没有用例名的崩溃信息。

## 修法

**缺陷一**：优先取 `deep`，取不到退到任意一条（这一步必须真的执行），
并把「四步是否都真的跑了」变成可断言的事实。

**缺陷二**：把断言收进 `await okA(...)`，让失败收敛成单项红。

## 验证

**缺陷二的 before / after**（同一次故意失败）：

| | 输出 |
|---|---|
| 修复前 | `❌ 测试失败: AssertionError: Missing expected rejection.` ——裸崩，无用例名，**无 `全部通过` 行**（整套中止） |
| 修复后 | `✘ addMemoryItem：空内容拒绝` ——单项红，套件跑完并报出总数 |

**顺带的信号**：单测 850 → **851**。多出来的正是 `propose_deletions` 那条——
它以前嵌在 `if` 里可能不执行，现在每次都跑。
