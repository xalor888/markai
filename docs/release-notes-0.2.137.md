# v0.2.137 — 大库「全部展开」一次挂 6182 个 DOM 节点

## 缺陷

书签树的 `visible` 展平**没有任何行数上限**：

```js
const out: VisibleNode[] = [];
const walk = (nodes, depth, chainMatched) => { ... out.push({node:n, depth}); ... };
walk(roots, 0, false);
return out;                    // ← 有多少行就挂多少个 DOM 节点
```

`expandedIds` 的 500 上限只限制**文件夹**数，不限制**总行数**（文件夹 + 其全部子书签）。

而 `TreeRow` 虽包了 `memo`——memo 只在**重渲染**时有用，首次挂载 N 个 DOM 节点照卡。

## 实测（真实浏览器，60 文件夹 × 100 书签 = 6060 条）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 一次性渲染行数 | **6,182** | **800**（上限） |
| 耗时 | **721ms** | **336ms** |

省下 5,382 行 DOM 节点。按此外推 2 万条的库约 2.4s，且 React 协调成本随规模超线性增长。

## 修法

树不是虚拟列表，但可以**只渲染前 800 行**，剩下的按需加载：

```
还有 5382 项未显示 · 点击继续加载
```

- **不能静默少显示一批**——所以必须给出口，并说清还剩多少
- 过滤/搜索时**不加帽**：那时行数是用户筛选的结果，砍掉会直接丢结果
- 展开状态或过滤词变化时回到默认帽：否则「收起后再展开」会停在上次的高帽上

## 验证

新增 8 项 e2e（真实浏览器量，不是离线推算）：

```
PASS 前置：大库种入成功
PASS 前置：重载后树上确实有大库数据
PASS 大库全部展开：把真实行数记下来（优化的对比基线）
PASS 大库全部展开后界面仍能响应
PASS 大库全部展开后有「显示更多」出口（不静默少显示一批） · 还有 5382 项未显示
PASS 「显示更多」说清还剩多少项
PASS 渲染行数被上限盖住（不再一次性挂 6000+ 个 DOM 节点）
PASS 点「显示更多」能继续加载（出口不是死的） · 800 → 1600
```

**证伪**：把上限改成 1000000（等于不设）→ 四条全红，行数回到 **6182**。

## 过程中栽的两个跟头

1. **测到的行数是 122 而不是 6061**：这个主页面目标已在后台跑了很久，Chrome 节流了它的
   定时器，书签监听器的去抖刷新一直没跑——树上还是旧数据（甚至还有早先已删掉的
   `bulkcap-104`）。**必须先 `Page.reload` 再量。**
2. **嵌套模板字面量**：种书签的代码里用了 `` `bigf-${i}` ``，反引号把外层提前终止。
   改字符串拼接。
