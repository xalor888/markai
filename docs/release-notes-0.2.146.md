# v0.2.146 — 取消功能的完整性修复

## 背景

连续三批修了「取消能生效」（0.2.141）、"报数量"（0.2.144）、"标中断"（0.2.145）这三个环节，但这轮发现了两个**逻辑缺陷**和一个**体验不一致**。

## 缺陷一：取消后的撤销历史分不出「已中断」

被取消的轮次和正常做完的轮次，在撤销历史里长得一模一样：

```
删除 1 项        ← 正常做完的
删除 1 项        ← 取消掉的半步
```

用户点了取消之后回头看历史，无法确认哪一条对应刚才那半步，也就不知道该不该撤销它。

**修法**：`UndoPoint.interrupted?: boolean` + 摘要后缀「（已中断）」

## 缺陷二：取消掉的改动被当成「什么都没做」

`retrySafety()` 只把 `status === 'done'` 算作「改过了」：

```ts
if (b.record.status !== 'done') continue;
if (MUTATING_TOOLS.has(b.record.name)) mutations++;
```

批量移动 100 条移到第 40 条时用户点取消 —— 那 40 条是**真的移走了**，撤销点里也有。但 canceled 不计入 mutations → 界面认为"这轮什么都没做、可以安全重来" → 用户重发同一句就会再移一遍。

**修法**：`retrySafety` 把 canceled 也计入 mutations。

取舍：宁可多提示一次"已经改过、要退回请点撤销"，也不能让用户重复执行造成数据错乱。

## 体验：取消看起来像报错

ToolStatus 只有 running | done | error，取消只能塞进 error —— 于是用户自己主动点的「停止」，显示成一个**红色警示三角 + 红字**，用的是"出错了"的视觉语言。

**修法**：ToolStatus 增加 canceled，ToolChip 用中性样式（CircleStop + "已停止"）。

## 验证

单测 **860 项**（+2）：
- PASS 写类工具被取消也算改动（否则重试会重复执行已落地的那部分）
- PASS 只读工具被取消不算改动（它本来就改不了东西）

证伪（撤回 canceled 计入）→ 转红：`❌ 取消的写类工具没有被算作改动`
