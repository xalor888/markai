# v0.2.156 — 「搜一个空格」= 搜出几乎所有书签

## 缺陷

`search_bookmarks` 的 schema 是：

```ts
query: z.string().min(1).max(100),
```

`" "`（一个空格）长度是 1，**通过校验**。

然后 `chrome.bookmarks.search(" ")` 会命中**任何标题里有空格的书签** ——
也就是几乎所有书签。工具把结果按 `limit`（默认上限 2000）截断后交给模型：

- 上下文被 2000 条无关结果占满
- 而模型以为自己搜到了想要的东西，不会去收窄条件

空白搜索本来就是无意义的输入，应该在入口拒掉，而不是让它变成一次"成功的"大查询。

## 实测

```
修复前：[DBG] query=" "  rejected=false
修复后：[DBG] query=" "  rejected=true  参数不合法：Too small: expected string to have >=1 characters
```

`"   "` 和 `"\t"` 同样处理。

## 修法

```ts
// trim 在前：`" "` 长度 1 原本能过校验，而 chrome.bookmarks.search(" ")
// 会命中任何标题里有空格的书签，等于把上限 2000 条无关结果灌进上下文
query: z.string().trim().min(1).max(100),
```

顺带：`"  hello  "` 现在会以 `hello` 去查，回显的 `query` 字段也是干净值。

## 顺带清掉一处我自己留下的重复

0.2.143 批量给所有长循环工具插 `throwIfAborted()` 时，`createBookmarks` 里被插了**两遍**
（注释和调用各重复一次），而且注释里的例子「如『子项不足，无需排序』」是从 `sortFolder`
误拷过去的 —— 放在**创建**函数里完全说不通。那 11 处复制粘贴的注释统一改成不绑定具体工具的
说明；`sortFolder` 里那一处保留（那里本来就该提排序）。

用户看不到这个，但它会误导下一个读代码的人，所以一起修了。

## 验证

新增 1 项单测（872 → **873**）：对 `" "` / `"   "` / `"\t"` 三种空白搜索词断言必须拒绝；
再传 `"  hello  "` 断言能命中且回显的 `query` 是 `hello`。

**证伪**（去掉 `.trim()`）→ 转红：
