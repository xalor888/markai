# v0.2.159 — 「你改过名」——不，我没有

## 缺陷

「一键去重」会给每一组重复附一句**为什么保留这条**。原来那句是：

> 它有自定义标题（改过名的通常是你在意的那条）

判据是：

```ts
function hasCustomTitle(n) {
  const t = (n.title || '').trim();
  if (!t) return false;
  return t !== (n.url ?? '').trim();
}
```

问题在于 —— **Chrome 收藏页面时，标题取的是页面标题**，几乎从不等于 URL。
所以这条对绝大多数书签**恒为真**：

```
两条都是普通页面标题（用户从没改过名）
  理由：它有自定义标题（改过名的通常是你在意的那条）   ← 假话
```

更糟的是：因为第 1 条规则永远打平，「自定义标题」这条其实**从来没决定过胜负**，
真正决定的是第 2/3 条（最近使用 / 收藏最早）。用户读到的解释与实际发生的事无关。

这是删除类操作上的错误解释——用户是靠这句话决定要不要点「确认删除」的。

## 附带：连「标题就是网址」也判成改过名

```
标题 'https://github.com/'  与  'https://github.com'
  理由：它有自定义标题   ← 两个都只是网址，只因尾斜杠不同
```

## 修法

1. 判据改成**「标题是否只是网址原文」**（`isUrlLikeTitle`）：与 URL 相同、或去掉协议/www/尾斜杠后相同，都算"没有信息量"。这类标题才不该优先保留。
2. 理由**按真正分出胜负的那一步生成**：拿冠军与亚军逐条比较，哪一步不同就说哪一步。

实测五种场景，理由都与实际决策一致：

| 场景 | 保留 | 理由 |
|---|---|---|
| 两条都是页面标题 | a（更早） | 它收藏得最早 |
| 网址原文 vs 可读标题 | human | 它的标题是给人看的，其余几条只是网址原文 |
| 都没好标题 → 最近使用 | recent | 它最近被使用过 |
| 都没用过 → 最早 | earlier | 它收藏得最早 |
| 完全相同 → id 稳定 | a1 | 按 id 稳定排序取第一条（其余条件相同） |

## 验证

新增 2 项单测（876 → **878**）：

- `没改过名时，理由不能声称「自定义标题 / 改过名」`
- `网址原文标题 vs 给人看的标题，优先保留后者（理由要说清）`

**证伪**（换回 0.2.158 的旧 keeper 逻辑）→ 转红：

```
✘ 保留规则：没改过名时，理由不能声称「自定义标题 / 改过名」
❌ 用户没改过名，理由却说改过名：它有自定义标题（改过名的通常是你在意的那条）
```

## 过程中修正的一个自造 bug

第一次实现时比较器符号写反了（`isUrlLikeTitle` 为真应当**排在后面**，写成了前面），
既有用例立刻转红。已修正，并由 878 项全绿确认。

## 一条措辞同步

既有用例的说明文字「保留 a（有自定义标题）」改为
「保留 a（标题可读、且创建更早）」——**断言本身没动**（保留 a、提议删 b/c），只是描述与事实对齐。
