# v0.2.160 — 删除超时后说「失败请重试」，其实可能已经删了

## 缺陷

确认删除的超时路径（30s）原话是：

> 删除执行未返回结果，请重试

但问题是：**可能已经删了**。

流程是：
1. `confirmDeletions` 先标记为 confirmed
2. background 收到请求开始删除（通常 <1s）
3. 若 SW 卡死/无响应 → Promise.race 触发 timeout → **已删成功但无结果**
4. 旧代码回退 pending + 提示"失败请重试"

结果是：**假的失败提示**误导用户，还会诱导二次发送删除请求——虽然 executor 对缺失书签安全（count++），但逻辑不清晰，用户体验也被欺骗。

## 修法

超时保持 confirmed，提示刷新即可；不触发额外的删除请求：

```ts
// 证伪前（旧行为）：status=pending, toast="请重试"
// 证伪后（新行为）：status=confirmed, toast="可能需要刷新以查看最新清单"
```

既避免误导，也防止二次发送造成的潜在风险。
