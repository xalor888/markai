# v0.2.161 — 「URL 格式无效」——那什么格式有效？

## 缺陷

两处提示只说了「发生了什么」，没说「接下来该做什么」：

| 提示 | 问题 |
|---|---|
| `URL 格式无效` | 用户不知道该改成什么样——是缺协议？多了空格？还是根本不支持这个协议？ |
| `Agent 正在处理中，请稍候` | 用户不知道要等多久、能不能取消、点「停止」按钮是否有效 |

这两条都是**用户会真实卡住**的地方：第一条发生在新建/编辑书签时，第二条发生在用户想
连续发消息时。只说「无效 / 请稍候」，等于把排查工作全丢给用户。

## 修法

补上可照做的下一步：

```ts
// URL 校验失败
pushToast('URL 格式无效', {
  description: '需要一个完整的网址，例如 https://example.com 或 https://example.com/path',
  variant: 'destructive',
});

// Agent 忙
pushToast('Agent 正在处理中，请稍候', {
  description: '等它完成或者点击「停止」按钮来取消当前任务',
});
```

两处 `URL 格式无效`（新建书签 / 编辑网址）和两处 `Agent 正在处理中`（`send` 的入口守卫）
全部补齐。
