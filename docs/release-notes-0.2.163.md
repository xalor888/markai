# v0.2.163 — 「72/72 通过」——其实脚本中途崩了

## 缺陷

这一条出自**我自己踩的坑**，所以先讲事实：

本轮开场跑基线时看到：

```
E2E 结果：72/72 通过 · 36.8s
```

我一度以为基线绿了。实际上那次 e2e **中途崩溃**，只跑了 72 项（正常是 199 项）。

脚本本身是对的——0.2.13x 已经把「跑挂 ≠ 通过」修过了，`crashed` 分支会打印
`E2E 执行中断` 并把退出码设为 1。问题在于**首行**：

```
E2E 结果：72/72 通过 · 36.8s          ← 眼睛先落在这
                                       
E2E 执行中断：...                      ← 补充说明在后面
（上面是中断前已完成的部分；中断不等于通过）
```

用 `grep "E2E 结果"` 取一行、或扫一眼摘要的人，读到的就是"全通过"。
**崩溃伪装成绿灯，比测试失败危险得多**——它会让后面所有"四道门全绿"的结论失去意义。

## 修法

把「不完整」写进首行，而不是只靠下面的说明：

```js
const headline = crashed
  ? `E2E 结果（不完整 · 执行中断）：${passedCount}/${results.length} 已完成项通过`
  : `E2E 结果：${passedCount}/${results.length} 通过`;
console.log(`\n${headline} · ${elapsed}s`);
```

- 正常跑完：`E2E 结果：199/199 通过 · 122.8s`（措辞不变，不制造噪音）
- 中途崩了：`E2E 结果（不完整 · 执行中断）：72/72 已完成项通过 · 36.8s`

## 验证

新增 1 项源码契约守卫（882 → **883**）：取脚本里「拼装文案 + 打印」的代码块
（**跳过注释行**——注释到不了运行时，与 `shortcut-contract` 守卫同判据），
断言该块同时含 `crashed` 与 `不完整`。

```
[DBG] 总结代码块: const headline = crashed ? `E2E 结果（不完整 · 执行中断）：…` : `E2E 结果：…`
全部通过：883 项 ✔
```

**证伪**（把 headline 改成无条件「通过」）→ 转红：

```
✘ e2e 总结行在执行中断时必须带“不完整”标记
❌ 中断时的首行必须带「不完整」字样，不能只靠下面的补充说明
```

## 这一条为什么值得单独发版

它不改善任何用户可见界面。但它决定**这个项目所有"基线绿"结论是否可信**——
七天来自主优化的每一次 commit 都以"四道门全绿"为前提，而这道门刚才差点骗过我自己。
