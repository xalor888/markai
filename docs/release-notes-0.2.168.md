# v0.2.168 — 不再把「思考」当成「没响应」

0.2.167 的首字节看门狗有一个错误假设：**120 秒没有字节 = 连接死了**。
推理模型思考几分钟是正常行为，于是它的思考被反复掐断、自动重试、从头再来。

## 修复

- **首字节超时不再自动重试**（所有模型）：没收到任何字节时无法区分「长思考」与「连接挂了」，自动重发只会把思考作废重来；现在超时后给出明确错误，由用户手动重试。
- **推理模型首字节窗口 120s → 480s**：目录 `reasoning.supported`、显式思考档位、模型名兜底三路判断。
- **状态从请求发出那一刻就是「模型思考中」**，不再先显示「连接模型」。
- **长时间无输出的提示从 30s 改到 60s**，文案明确写「不会自动重试」，并保留「停止」按钮。
- 自动重试只保留给 5xx、429、网络错误、中途断流；中途断流仍会先作废半截内容再重发。

# 追加修复：整页被书签树撑满（"一打开就放大、缩不回去"）

## 现象

完整页（`page.html`）打开后只剩一棵**横向撑满整个窗口**的书签树：中栏列表不见、Agent 面板不见，
而且没有任何手柄/开关能把它缩回去。顶栏、字号、行高都正常——不是浏览器缩放，`⌘-` / `⌘0` 自然不会有用。

## 根因

树列的宽度写在了 `ErrorBoundary` 上：

```tsx
<ErrorBoundary area="书签树" className="w-56 shrink-0">   // ← 这层盒子不存在
```

`ErrorBoundary` 为了"错误态之外零布局影响"在正常渲染时是 `display: contents`，
**它没有盒子，写在它身上的 `w-56 shrink-0` 被整条丢弃**。
树的宽度于是退回 `max-content`：库里只要有一条超长标题（把整篇标题或 URL 存进来很常见），
树的 max-content 就顶到视口宽度 ——

- 中栏 `flex-1 min-w-0` 被挤成 **0 宽**（看起来"列表没了"）；
- Agent 面板 `shrink-0 360` 被顶出 `overflow-hidden` 的可视区（看起来"面板也没了"）。

实测（1700×836 视口，库里一条 5031px 宽的超长标题）：

| | 树 | 中栏列表 | 文档横向溢出 |
| --- | --- | --- | --- |
| 修复前 | 1684（被视口裁到） | 0 | 有 |
| 修复后 | 224 | 1116 | 无 |

侧边栏同一处问题：抽屉的 `absolute inset-y-0 left-0 z-30 w-52` 也写在 ErrorBoundary 上，
浮层退化成文档流里的宽块（420 宽面板实测树 5128px、列表 0）。一并修好：抽屉 208px、绝对定位生效。

## 修法

1. **宽度挂到真实盒子上**：完整页 `<div class="flex w-56 min-w-0 shrink-0 flex-col overflow-hidden">`，
   侧边栏 `<div class="absolute inset-y-0 left-0 z-30 w-52 min-w-0">`，ErrorBoundary 只负责兜错。
2. **树根加护栏**：`w-full min-w-0 overflow-hidden` —— 列宽由外层给定，内容不得反向撑开。
3. **标题 `truncate` 收口**：长标题省略号 + 行级 tooltip 显示全文。
4. `ErrorBoundary` 的 `className` 文档里写死一句：**这是错误态类名，布局类名写这里会被静默丢弃**。
5. 两条不变量进单测（T28）：`w-56/w-52` 不许出现在 ErrorBoundary 上；树根必须带 `w-full min-w-0 overflow-hidden`。

生效方式：重新构建并**在 `chrome://extensions` 点「重新加载」**（或重新装 zip）——旧页面不会自己换掉。
