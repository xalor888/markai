# v0.2.173 — 书签栏不是全库：多根书签库不再被当成一个根

## 一、问题

用户让 Agent 整理书签。它先执行 `list_bookmarks(parentId="5")`，看到「书签栏」下 16 个文件夹、0 条直接子书签，随后把「其他书签」根层的 2 条书签称为「游离书签」，建议搬进书签栏的分类里。

这个判断不成立：

- **Chrome 的书签库有多个根**：书签栏、其他书签、移动设备。书签栏只是其中一个；
- 「其他书签」根层的书签是合法存放位置，不是垃圾，也不叫「游离」；
- 未经用户明确要求，Agent 不应该跨根搬迁；
- `organize_folder` 只移动目标文件夹的**直接**子书签；根层全是文件夹、书签都在下一层时，硬造同名分类只会破坏已有结构。拒绝执行本身是对的，但之前的范围判断和建议是错的。

## 二、修法

### 1. 工具返回先给「根分布」

`list_all_folders` 现在返回：

- 顶部 `roots`：每个根的书签数、文件夹数、直接子书签数；
- 每个文件夹：`bookmarks` 递归书签数（这个分类下面实际有多少条）、`folders` 递归子文件夹数、`root` 所属根；
- 旧的 `count`（直接子项数）保留兼容。

`list_bookmarks` 列到根层时，额外返回：

- `scope: "root"`；
- `directBookmarks / directFolders`；
- `roots`：所有根的书签分布。

这样模型在列「书签栏」时就能同时看到「其他书签还有多少条」，不会再把它当成全库。

### 2. 系统提示增加三条硬规则

- **书签栏 ≠ 全库**：用户说「整理收藏夹 / 整理书签」但没指定文件夹时，先调用 `stats` 看各根分布，再问清或明确选择范围；不要默认只查书签栏。
- **其他书签 / 移动设备的根级书签是合法存放位置，不叫“游离书签”**；除非用户明确要求合并根，不要擅自搬进书签栏（或反向搬）。
- `organize_folder` 只处理直接子书签；根层全是分类文件夹时，先用 `list_all_folders` 看递归书签数，再问用户是否深入某个分类，不要为了“有事可做”硬造同名分类。

## 四、影响

- 列根层时输出会比之前多一个 `roots` 数组；这是有意的，用来阻止“书签栏 = 全库”的误判。
- `list_all_folders` 每项多两个整数字段，分页与原有字段不变。
- 没有任何写操作被放宽；跨根搬迁仍然只能由用户明确要求后执行。
