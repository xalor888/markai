# v0.2.174 — 深整理、少空转、少问一句

这一版只做用户能感觉到的三件事：Agent 能真正整理“大类下面的子类”，不再卡在“直接子书签为 0”；能安全地递归，也能安全地放弃；界面上多选和配置入口更直白。

## 一、Agent：深度整理终于有工具路径

### 问题

真实书签库里，大类（AI 工具、开发与编程）通常只有子文件夹，书签都在下一层。`organize_folder` 过去只接受目标文件夹的**直接**子书签，于是 Agent 面对 142 条、10 个子类的「AI 工具」只能拒绝，或硬造同名分类。用户会觉得“这个 Agent 什么都做不了”。

### 修法

`organize_folder` 新增显式 `scope`：

- `scope:"direct"`（默认）：保持旧语义，只移动直接子书签；
- `scope:"deep"`：递归目标文件夹的整棵子树，接受任意层子文件夹里的书签；仍然**只接受目标子树内**的书签，子树外一律拒绝；
- 递归范围必须显式传，默认不扩大，避免误伤用户没让动的深层书签；
- 深整理会记录每条书签原本的父文件夹。暂存批次「放弃」时逐条回到**各自原文件夹**，不会把十个子类的书签平铺回目标根；
- 直接落位时，如果旧子文件夹被清空，返回值列出 `emptiedFolders` 并明确说明“不会自动删除”；
- 子树外的书签、文件夹、不存在的 id 各有不同错误与下一步，模型不会原样重试。

同时调整系统提示：目标文件夹只有子文件夹、书签都在下一层时，先看结构；用户明确要整理整个大类时可显式用 `scope:"deep"`；不要为了“有事可做”硬造同名分类。

### 少问一句

用户说“整理书签”但没指定范围时，Agent 现在被要求：

- 先看各根/文件夹结构；
- **能安全形成计划就直接调用 `organize_folder`（默认暂存）生成可确认批次**；
- 不要只输出一段分析再问“需要我执行吗”；
- 只有跨根搬迁、删除、范围本身有歧义时才先问。
