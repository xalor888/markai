# v0.2.175 — 侧边栏重做、语义搜索、点子管家与对外接口

这一版是四条并行工作线的合并交付：**左栏更像 IDE、搜索能听懂意思、点子从“建议”变成能接着做事的 Agent、外部 Agent 可以安全地读写书签**。同时补上检查更新、聊天发图、宠物自定义与液态玻璃 v2。

## 一、侧边栏：从“能看”到“能干活”

- **排序可选**：手动顺序 / 按名称 / 按条目数 / 按最近添加，选择跨会话保留；排序只影响显示，拖拽仍按真实位置落位。
- **两档密度**：舒适 / 紧凑，行高 32px ↔ 26px，窄侧栏一屏能多看三四行。
- **三个根各认各的**：书签栏用星标、其他书签用打开的书夹、移动设备用手机图标；不按下标猜，id 与中英文标题双保险。
- **根行显示递归总数**，子文件夹显示直接子项数——不用逐层点进去才知道规模。
- **选中态左侧指示条**：和列表同一套语言，不再靠整块高亮去喊；拖拽行间定位条单独一套半透明样式，两者不混。
- **头部收敛为单行**：完整页 224px、侧栏浮层 208px 下，「排序 / 密度 / 展开折叠」不再被压成竖排；浮层只保留逐级展开，完整页才给「全部展开 / 折叠」。

## 二、检查更新

- 顶栏「更多」里有「检查更新」，有新版本时菜单项带小圆点；
- 数据来自 GitHub Releases（无 token），只做告知：扩展不能自动安装，所以文案只说「发现新版本 / 已是最新版本」，并把发布页交给浏览器；
- 失败按网络 / 限流 / 解析分类，各自说明原因，重试按钮不承诺“一定成功”；
- 小圆点只认 **30 分钟内的新鲜缓存**，过期结论不会一直亮着。

## 三、聊天发送图片

- 选图、粘贴、拖拽三条入口都能进；非图片与超限文件当场说明原因，不静默丢弃；
- 进内存前先压到**长边 1024、单张 300KB 以内，一轮最多 3 张**——图片会随消息落进 `chrome.storage.local`，原图一张就能把 6 MiB 聊天预算挤爆；
- 走 OpenAI 兼容的 `image_url`（data URL 内联），文本在前、图片在后；纯图片无文字时补一句明确任务，不发空 content；
- 历史里只保留 `[附图：文件名]` 占位，不把 base64 存进对话记录；token 预算按张数计，不按 base64 长度算。

## 四、宠物工作室

- 顶栏进「制作宠物」：轮廓 / 配色 / 配件 / 名字与口头禅四组控件，左边是真组件预览（不是截图），四种心情轮播；
- 所有改动即时生效，预览与页面里那只读同一个 store，关掉面板就是保存，没有“取消 / 保存”两套语义；
- 造型全部内联 SVG，零图片资源、任意尺寸清晰、深色主题自动换配色；名字与口头禅有长度上限并做控制符净化，不会出现无名宠物；
- 对外接口（MCP / CLI 桥）可以读取与设置宠物造型，参数非法时回落默认而不是报错中断。

## 五、液态玻璃 v2、动效与外观自定义

- **玻璃层 v2**：底色层 + conic 四向色带边缘 + 内高光 + 外投影；玻璃强度 0–100 映射到透明度与模糊，0 即近实心（弱机省电），上限受 AA 约束（小字不能糊）；
- **指针反光**：文档级 `pointermove` 只给最近的玻璃面写坐标，无观察器、无 rAF；
- **动效 token**：`full / calm / off` 三档，`off` 同时尊重 `prefers-reduced-motion`；
- **外观设置**：6 套强调色、4 种背景（无 / 极光 / 网格 / 自定义图）、背景压暗、玻璃强度、界面密度；
- 自定义背景图在设置页压到**长边 1920、800KB 以内**再落盘，避免把 storage 写满；
- 一处硬约束：`backdrop-filter: url(#svgFilter)` 在 `chrome-extension://` 下会被静默丢弃，所以玻璃只用真实模糊 + 光学层，不做假折射。

## 六、本地向量混合检索

- 本地 **384 维特征哈希**向量（`local-hash-v2`），零网络、零额外权限；关键词与向量混合排序，纯语义命中不会被词汇锚点过滤掉；
- 索引按 id 哈希**分片**（每片 ≤200 条），改一条书签只重写命中的那一片，不整库重写；
- **8 MiB 存储预算**：超预算时按「最近使用 → 最近收藏」保留向量，其余降级为仅关键词，状态里如实计数，不会把聊天记录和设置挤没；
- 可选远端嵌入（`remote:<model>`），本地与远端向量不混用，模型标识写进 manifest，换模型自动重建；
- 接入三处：⌘K 命令面板、顶栏搜索、Agent 的 `search_bookmarks`。

## 七、点子管家

- 规则层先跑：老旧、重复、空文件夹、单域名散落、断链、根级未分类——**每条都带真实统计与样本书签 id**，点开就能核对；没配 AI 也有完整点子，不会整块空白；
- 模型只做增强：只发聚合统计 + 最多 30 条样本标题，不发完整 URL 列表；输出必须严格 JSON，解析失败整轮丢弃；解析后还过滤 kind、count 不得超过真实书签数、禁止“我已经帮你删了”这类越权表述；
- 同一条点子 7 天冷却，不会每次打开都是同一批；
- **简单清理**：勾选类别 → 算出“将影响 N 条” → 生成指令交给 Agent 走既有暂存/确认链路；断链在检测前标「待检测」，不猜数字；未勾选或库里没问题时不生成空指令；
- 删除永远只提议、不执行；点子的「开始」只是把可改的指令填进输入框。
- 设置页「点子」不再是占位：显示当前来源（仅规则 / 规则 + 模型）、冷却表条数，并可一键清空让被忽略的点子重新出现。

## 八、对外接口：MCP / CLI / Skill

- `tools/markai-bridge.mjs` 在本机回环地址持端口，扩展长轮询领活；MCP 走 stdio，实现 `initialize` / `tools/list` / `tools/call` / `ping`；
- 三种接入（MCP / CLI / Skill）共用**同一条队列、同一个 token、同一份审计**，不存在第二条绕过安全模型的路径；
- 只监听 `127.0.0.1`；每请求 Bearer token（常量时间比较）；工具白名单桥与扩展各校验一次；写操作默认关闭；
- **删除永远只提议**：即使聊天 Agent 开了「无需确认」，外部调用也强制走确认——这条由 `ToolContext.external` 在工具层强制，有测试守着；
- 11 个工具：`list_bookmarks` / `search_bookmarks` / `get_folder_path` / `list_all_folders` / `stats`（只读）+ `create_folder` / `create_bookmark` / `move_bookmark` / `rename_bookmark` / `update_url` / `propose_deletions`（写）；
- 附带 CLI（`tools/markai.mjs`）、Skill 安装器（`tools/install-skill.mjs`）与完整文档 `docs/external-api.md`。

## 九、本轮修复

- **Chrome 158 起书签加密存储**：无人值守的临时 profile 拿不到 Keychain 授权时，`chrome.bookmarks.getTree()` 回调永不触发、Promise 永不 resolve、`lastError` 还是空。6 个真机脚本统一加 `--use-mock-keychain`，e2e 不再莫名挂起；

- **宠物可访问名称断言**：宠物支持自定义名字后，不再钉死「书签精灵」四个字，改为结构断言（`名字：状态`），与 `agent.test.ts` 的口径一致。

## 十一、边界

- 删除安全闸门、撤销、暂存确认全部不变；外部调用额外加严，永不自动删除；
- 语义索引只是“更好搜”的增强，超预算会降级并如实计数，不影响关键词搜索；
- 远端向量默认关闭，可在设置页单独关；本地索引只增加结果、不改变关键词命中，可在设置页随时取消或重建；
- 点子规则始终可用（本地确定性扫描），模型增强跟随「AI 服务」配置；设置页可清空冷却表，让被忽略的点子重新出现；
- 外观（强调色 / 背景 / 动效 / 密度）全部可恢复默认，动效 `off` 同时尊重系统「减少动态效果」。
