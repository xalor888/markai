# MarkAI v0.2.24 发布说明

## 概述

v0.2.24 把「v0.2.23 之后已经写完、但当时没随版本发出去」的那批加固真正发布了。
v0.2.23 的 tag/zip 打的是 **441 项测试 / 135 条反证**的状态，v0.2.24 才是 **468 项 / 161 条**这一批的产物。
同时加固了发版通道本身：从现在起，产物不对就不会有 Release。

## 关键修复

1. **文件夹置顶比较器写反（真实产品 bug，用户可见）**
   `sort_folder`（`src/lib/ai/tools.ts`）与完整页书签列表（`src/components/bookmark-list/bookmark-list.tsx`）
   都写成 `(b.url ? 1 : 0) - (a.url ? 1 : 0)` —— 注释与 README 都声称「文件夹置顶」，
   而这行代码实际把**书签**排在最前面。两处均改为 `(a.url ? 1 : 0) - (b.url ? 1 : 0)`。
   发现方式值得记一笔：它不是"读代码看出来的"，是一条被判为 exhausted 的新测试变红后
   逐处对照工作树抓到的——**测试是对的，实现是错的**。

2. **撤销快照的递归深度上限 off-by-one**
   `toSnapshot` 用 `depth > 64` 判断，会产出 depth 65 的节点，而 `restoreSubtree` 的守卫在同一个界上拒绝，
   形成「**存得下、还原不了**」——快照留在存储里，点撤销时失败。改为 `depth >= 64`。

3. **两处测试类型错误**：`assert.match(ToolOutput, …)` 未取 `.result`，此前 `tsc` 直接红。

4. **清掉 `public/store/test.txt`**：4 字节、内容是 `test`，此前**真的会被打进扩展包**
   （`npm run build` 的产物清单里就有这一行）。已移除。

## 发版通道加固（`.github/workflows/release.yml`）

5. **新增「校验产物」硬门禁**：在 `npm run zip` 之后、创建 Release 之前，拿 zip 里的 `manifest.json`
   与 `package.json`、（tag 触发时）tag 名三方对齐，再检查 `manifest_version == 3` 与五个入口文件
   （`background.js` / `sidepanel.html` / `page.html` / `popup.html` / `options.html`）是否齐全。
   任一条不满足即非零退出，**Release 不会被创建**。这是发版手册 §3 那步人工核对的机器化版本。
   本地已实测三条路径：正常通过；tag 名不符（`v9.9.9`）退出 1；产物文件不存在退出 1。

6. **改正 `workflow_dispatch` 的注释**：它此前写着「手动触发同样发布」，而下一步的 `if` 只认
   `refs/tags/v` —— 手动触发永远进不去。注释与行为相反，照注释理解就会以为手动跑一次也能出 Release。
   现在注释如实写明：手动触发只构建 + 上传 artifact，**不建 Release**。

7. **校验步骤按版本号拼确切文件名**，不用 `ls .output/*.zip | head -1`：
   `.output` 会攒下每一版 zip，而 `ls` 是字典序（`markai-0.2.10-chrome.zip` 排在 `markai-0.2.9-chrome.zip` 前），
   `head -1` 挑中的是旧产物。CI 上碰不到，但本地调试会骗人。

## 许可

8. **补上 MIT 许可**（`LICENSE` + `package.json` 的 `license` 字段 + README「许可」章节）。
   此前这个公开仓库没有任何 LICENSE，按默认规则等于「保留所有权利」——别人不能合法地
   使用/修改/再分发。现在可自由使用、修改、再分发（含商用），只需保留版权与许可声明。

## 测试与反证体系

- 全量自动化测试：**468 项全绿**；
- 行为级反证（Falsification）：共 **161 条**。本版发布时**实测跑完 15 条，全部 `RED ✔`**
  （无 `GREEN ✘`、无 `RED?`），其余 146 条为「锚点静态校验通过」——**全量仍未跑完**
  （一条约 17 秒，161 条约 46 分钟）。这一缺口如实记在 `DIRECTION.md` §10，不当成已解决。
- 反证脚本新增**中断自保**：改写源码前落盘 `.falsify-pending.json`，恢复后删除，
  下次启动发现残留自动还原，并对 SIGINT/SIGTERM/SIGHUP 优雅还原。
  （此前被强杀会把「回滚态」留在工作区，而它看起来完全像真代码——本项目因此吃过两次亏。）
- 反证脚本新增 `--only=用例名关键字` 定向复核：改了几处实现就能只验那几条，不必等一小时。

## 升级建议与已知事项

- **无破坏性变更**：配置与操作历史完全向后兼容。
- **建议升级**：本版修掉了「宣称文件夹置顶、实际把书签排在最前」这一用户可见的错误排序，以及
  「快照存得下、撤销还原不了」的深度边界缺陷。
- **真机验证仍是空白**：本版的证据是「替身测试 + 产物结构校验 + 部分反证」，
  **不构成**在真实 Chrome 里的行为证明（拖拽手感、撤销按钮、Service Worker 回收后的存储表现）。这属于 P3。
- 产物资产只有 **chrome zip**（MV3，Chrome/Edge 手动加载）；不产出 Firefox 产物，原因见 `docs/release.md` §4.5。
