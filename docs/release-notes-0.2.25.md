# MarkAI v0.2.25 发布说明

## 概述

v0.2.25 修掉一个**从上线起就完全失效、且失败被完全静默**的功能：原生右键菜单。
问题由用户报告发现——控制台里一条未捕获的 Promise 拒绝，扩展右键里什么都没有。

## 根因（两层，叠在一起才这么难查）

1. **菜单项用了 Chrome 不存在的上下文取值**：5 个菜单项以 `contexts: ['bookmark']` 注册，
   而 **Chrome 的 `contextMenus` 没有 `bookmark` 上下文**——那是 Firefox `menus` API 的取值。
   Chrome 只接受 14 个：`all / page / frame / selection / link / editable / image / video /
   audio / launcher / browser_action / page_action / action / tab`。旧代码里那句
   「'bookmark' 上下文是较新的 Chrome API，@types/chrome 尚未收录」的注释正是被 Firefox
   文档带偏的产物，`as unknown as` 断言把类型检查也一起绕过了。
   **后果**：这 5 个菜单项从上线起**一个都没注册成功**。
2. **失败被静默吞掉**：旧代码注册后只查 `chrome.runtime.lastError`，而 MV3 下不传 callback 时
   `create` 返回 **Promise**、校验失败走 **Promise 拒绝**——那句 `console.warn` 是死代码，
   一次都没打过。失败的唯一出口就是控制台里那条 uncaught，用户不问就永远不知道。

## 能力边界（如实说明，不是这次没做好，是做不了）

扩展无法向 `chrome://bookmarks` 注入，`contextMenus` 也没有书签上下文——**原生书签管理器的
右键菜单在 Chrome 上无法实现**。书签维度的「整理此文件夹 / 分析此书签」一直在 MarkAI 自己的
书签树右键里（侧边栏与完整页），能力没有丢。README 与权限文档的相应表述已同步更正
（旧文档声称「浏览器书签上右键」，那是做不到的事）。

## 修法

1. **入口换成扩展图标（action）右键**：打开 MarkAI 管理面板 / 在 MarkAI 完整页打开 /
   让 MarkAI 整理全部书签（新增的整库指令，不需要先选中什么）。
2. **注册逻辑抽成可单测的 `src/lib/ai/context-menus.ts`**：
   - 注册前按 **Chrome 上下文白名单**校验，非法取值在本地就被拦下（不发放给浏览器）；
   - **逐项独立记账**，一项失败不牵连其余；
   - **同时覆盖「Promise 拒绝」与「lastError」两种运行形态**（两种真实浏览器行为都抓得住）；
   - 返回成败清单，**全部失败时用工具栏提示主动告警**（badge + 悬停说明），不再只躺在控制台。
3. **顺带修掉一个连带 bug**：action 上下文的点击数据**不带 bookmarkId**，而旧的指令装配
   不先区分菜单项就查节点——点「整理全部书签」会收到「右键的书签已被删除或不可用」的假提示。
   现在 `markai:tidy-all` / `markai:open` 走不依赖书签目标的独立分支。

## 测试与反证

- 全量自动化测试：**478 项全绿**（468 → 478，新增 T69 十条：白名单 / id 唯一 / 逐项记账 /
  两种失败形态 / `bookmark` 取值被本地拦下 / 空 contexts 被拦下 / 无书签上下文不报假提示）。
- 行为级反证：共 **164 条**（161 → 164）。本版发布前对**改动涉及的 9 条**做了定向实跑
  （`--only`，含 3 条本轮新增），**全部 `RED ✔`**；全量仍未跑完（一条 ≈ 17 秒，164 条约 46 分钟），
  这一缺口继续如实记在 `DIRECTION.md` §10/§11。
- 顺带修正一条**历史遗留的反证 expectFail**：`buildInstruction 丢失失效节点友好提示` 此前只有
  「锚点静态校验」从未实跑，定向复核时暴露出它期望的首败用例名写错（实际首败是 T40 的
  notice 路径用例，先于 T68 执行），已按实际首败更正并复核通过。
- 产物实测：构建后的 `background.js` 中菜单注册为 `contexts:["action"]` ×4，
  不含任何 bookmark 上下文。

## 升级建议与已知事项

- **无破坏性变更**：配置、聊天与撤销记录完全向后兼容。
- **建议升级**：本版让「扩展图标右键」从"从未存在过"变为真实可用，并保证同类失败
  （注册整体失败）今后会以工具栏提示的形式被看见。
- `markai:organize` / `markai:analyze` 的指令装配与失效节点提示**保留但当前没有任何菜单注册**
  （Chrome 上无处可挂）；若上游将来支持书签上下文，注册进来即可直接用。
- **真机验证仍是空白**：证据是「替身测试 + 产物结构校验 + 定向反证」，不构成在真实 Chrome 里
  的行为证明（P3）。
- 产物资产只有 **chrome zip**（MV3，Chrome/Edge 手动加载）；不产出 Firefox 产物，
  原因见 `docs/release.md` §4.5。
