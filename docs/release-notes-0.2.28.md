# v0.2.28 — UI 视觉系统整修

一次**只动视觉、不动布局与交互**的整修：修掉一处确凿 bug，统一字号/圆角/间距/描边的标尺，去掉重复入口，补上此前缺失的设计 token。

## 一、确凿 bug：撤销计数徽标是"裸"的

`chat-panel.tsx` 的撤销徽标用了 `bg-primary` / `text-primary-foreground`，而 `main.css` 里**根本没有 `primary` 这个 token**（只有 accent / success / destructive）。

Tailwind v4 对未定义的颜色**静默不生成任何 CSS**——不报错、不警告。查构建产物可证：`bg-accent` 有 1 条规则，`bg-primary` **0 条**。于是那枚徽标没有背景色、文字也是继承色，浅色模式下几乎看不见。

而 `compile` / `test` / `build` **全绿**——这类 bug 在 CI 里没有任何信号。

## 二、统一视觉标尺

`main.css` 里的铁律此前只写在注释里，代码里没遵守：

| 项 | 改前 | 改后 |
|---|---|---|
| 深色主题底色 | `#0f0911` / `#16111c`（**偏紫**） | `#0e1116` / `#151a21`（冷灰，与浅色同色系） |
| 小字号 | 9px / 10px / 11px 三档混用 | 只留 `2xs=11px` 一档，9/10px 全部废除 |
| 圆角 | `rounded-sm/md/lg` 随意混用 | 落到 `xs=4 / sm=6 / md=8 / lg=10 / xl=12` 五档标尺 |
| 行高 | 列表行 h-9、树行 h-7、顶栏 h-10 各自为政 | 树头与中栏工具栏同为 h-10（两栏横条对齐），列表行 h-10 |
| 硬编码色 | `from-indigo-500/40`、`text-white` | 全部换成 token（`from-accent/40`、`text-accent-foreground`） |

深色偏紫这条尤其值得记：浅色是 Slate「零紫零品红」，深色却是另一套紫调，两套主题放在一起像两个产品。

## 三、去掉重复入口

**设置入口在同屏出现两次**：Workspace 顶栏一个、聊天面板头部一个。已删掉聊天面板头部那个（它与 Workspace 顶栏的按钮完全重复），保留顶栏的。

## 四、新增 token

- `--color-bubble`：助手气泡底色。原用 `bg-muted/45`，半透明在深色模式下几乎看不出差异，等于没分层。现在浅色 `#f2f4f8` / 深色 `#1a2029`，两套各自实心定义。

## 五、新增两条守卫（反证时抓到守卫自身的 bug）

T72 把「类名 → token 定义」的关系钉死：任何 `bg-*` / `text-*` / `border-*` 引用的颜色 token，若 `main.css` 里没定义，测试直接失败。

写完立刻做反证，**两条都报 `GREEN ✘`（假绿）**，查下来是两个真问题：

1. **守卫自己有解构 bug**：`for (const [key, hex] of matchAll(...))` —— `matchAll` 的第 0 项是整串、第 1、2 项才是捕获组。写成 `[key, hex]` 会把整串当 key、把 token 名（如 `background`）当 hex，`parseInt('ba', 16)` → `NaN`，"深色不得偏紫"判据**恒为假**。这条守卫从写下来就没生效过。已改为 `m[1]!` / `m[2]!` 并显式跳过 NaN。
2. **断裂守卫漏掉一类真实故障**：token 只在浅色 `@theme` 里定义时，Tailwind **仍会生成**这个类（所以第一条守卫抓不到），但深色模式下会静默沿用浅色值——例如 `bg-bubble` 若只在浅色定义，深色下就是近白底 + 深色字。已加判据：`@theme` 与 `.dark` 两块的 token 集合必须完全一致。

修复后反证 `RED ✔`。
