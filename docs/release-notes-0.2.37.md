# v0.2.37 — 自诊断与自修复

上一版留下的问题很具体：**扩展出问题时，你只能看到一个红色感叹号**。
点开是一串英文栈，既看不出严重程度，也不知道该修还是该删。

这一版把"诊断"做成了产品能力。

## 打开设置页就知道哪里不对

设置页第一屏现在是**健康检查**：

```
健康分 79/100
2 个问题，其中 1 个可一键修复
```

下面逐条列出、每条都带证据（不是一个模糊的感叹号）：

- **AI 服务还没配完** — 缺少：API Key。在此之前，自动整理只会用本地规则，对话功能会直接失败。
- **2 个书签找不到父文件夹** — 它们不会出现在任何树里，但仍占着数据库。通常是别的工具异常写入留下的。
- **最近一次 AI 调用失败** — `The operation was aborted due to timeout`
- **自定义请求头有写错的行** — 指出是第几行、哪几行，一键删掉写错的行
- **3 个撤销点已损坏** — 结构不完整，点「撤销」会失败或什么都撤不回
- **5 条记录已经无法撤销** — 对应的撤销点被上限挤掉了，面板上不会再显示点了没用的按钮

## 一键修复，但有一个硬边界

能自动修的：配置缺项、Base URL 格式、写错的请求头、损坏的撤销点、超量的记录、异常退出计数。

**不让自动修的：任何涉及你书签的事情。**

这条边界写死在代码里（`src/lib/health/fixes.ts` 顶部）：

> 自动修复只允许改动 MarkAI 自己的元数据（配置 / 撤销点 / 整理记录 / 运行时标记），
> 永远不会移动、删除、重命名用户的任何书签或文件夹。

书签结构的问题（孤儿节点、同名文件夹、空文件夹太多、嵌套过深）**只报告，给手动指引**。
你已经被"自动批量搬书签"坑过一次，不能再有第二次。

e2e 里专门钉了一条：点「修复全部」前后，书签总数必须完全一致。

## 复制诊断报告

右上角一个按钮，把这台机器的诊断压成一段纯文本：

```
MarkAI 诊断报告
版本 0.2.37 · Mozilla/5.0 ...
健康分 79/100 · 2 个问题

[high] config.incomplete — AI 服务还没配完
  缺少：API Key。...
  建议：到服务商后台复制一个 Key 填进来。
```

贴过来就能定位，不用再靠描述"那个感叹号长什么样"。

## 入口

- 设置页第一屏（打开就会自动体检一次）
- 书签页 `⋯` → **健康检查**，直接跳到这一节

## 工程

- 新增 `src/lib/health/`：`types.ts` / `diagnostics.ts`（纯函数）/ `fixes.ts` / `index.ts`
- 诊断是**纯函数**：输入只读快照，不碰 chrome、不发网络请求，因此能在单测里穷举（T102 共 21 条）
- 修复**幂等**且一条失败不影响其他；`chrome.permissions` 不存在时也不会让整次体检崩掉
- 单测 682 → **703**；e2e 22 → **25**（新增：健康分渲染、复制报告、修复不动书签）
