# v0.2.38 — 退出不再丢掉正在生成的回复

## 你报的问题

> 我一旦退出，它就变成「模型未返回任何内容，请点击重试重新生成」。

这是真 bug，而且是两处错误叠在一起。

### 错误一：内容真的丢了

流式回复的每一个增量只更新了**内存里的 store**，`_persist()` 只在两个时刻被调用：
「消息发出时」和「生成结束时」。

所以生成到一半关掉侧边栏 / 切走页面 → 这段内容从来没进过磁盘 → 重新打开只剩一条空消息。

**修法**：生成过程中每 800ms 落一次盘；页面 `pagehide` / 切到后台时再强制落一次。
现在中途退出**最多丢最近 800ms 的字**，而不是整段。

### 错误二：说法也是错的

空回复被一律写成「Agent 未返回内容」。但"被打断"和"模型真的没说话"是两件事：

- **被打断**：不是模型的错，已收到的部分还在，重试只是把后半截补上；
- **真的空回复**：模型确实没说话。

现在按 `interrupted` 区分：

- 一个字都没收到 → 「生成被打断了，还没收到内容。可点击 ↻ 重新生成」
- 收到了半截 → 保留全部内容，末尾加一句「生成被打断，以上是已收到的部分」

### 怎么判断"被打断"

消息上带一个 `streaming` 标记，随落盘一起写下去。
重新打开时凡还挂着 `streaming` 的，都是上次被强杀的（关侧边栏 / 进程被回收），
不会有 `chat:done` 再来——于是在 `load()` 里判定为 `interrupted`。

不这么做的话，要么界面永远转圈、输入框一直锁着，要么被当成空回复。

## 回归

新增 T103 三条：

1. `flushStreamPersist()` 确实触发落盘（不再只等 `chat:done`）；
2. 恢复时残留的 `streaming` 被判成 `interrupted`，**已收到的文本一字不少**；
3. 文案必须区分「被打断」与「未返回内容」。
