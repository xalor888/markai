# v0.2.41 — 书签加载失败时不再"一片空白"

## 加载失败现在会说话

以前 `getTree` 失败时，只有**书签树**里显示「加载失败 + 重试」。
但 0.2.35 起紧凑布局的树**默认是收起的**——于是你看到的是一个空列表：
既不知道出错了，也没有重试入口，第一反应是"书签全没了"。

现在列表上方会出现一条横幅：

```
⚠ 书签加载失败：<原因>                    [重试]
```

旧数据保留在下方（失败不代表数据没了），重试成功后横幅自动消失。

## 测试补强（这一版的重点）

**撤销的端到端覆盖**——这是你最在意的那条路，而 e2e 里一次都没跑过：

- 造「GitHub」文件夹 + github.com 书签 → 本地规则自动整理把它搬进去（不需要 AI）
- 打开整理记录 → 那条有可点的「撤销」
- 点下去 → 书签的 parentId 必须真的回到书签栏

**健康检查的修复**——以前只证明"修复没搞坏书签"，现在证明"修复真的修好了"：
种一个写错的自定义请求头，检测 → 点修复 → storage 里坏行消失、合法行保留。

两项都做了证伪：把实现改坏，测试立刻转红。

## 性能基线（只测量，未改动）

- 3000 条书签库，设置页健康检查 **146ms** 出分
- 3000 条书签打开文件夹渲染 **303ms**

都不需要优化，记为基线，以后改动超过这个数就得解释。
