# v0.2.43 — 健康检查不再误报「书签找不到父文件夹」

## 这是假警报，而且很吓人

0.2.37 的健康检查会这样报：

> **2 个书签找不到父文件夹**
> 它们不会出现在任何树里，但仍占着数据库。通常是别的工具异常写入留下的。

这句话会让任何人以为自己的书签库坏了。

实际上——**它们是正常的书签**。问题出在判断方法上。

## 根因

Chrome 的 `chrome.bookmarks.search({})` **不返回根文件夹**（书签栏 / 其他书签 / 移动设备）。

而原来的判据是：

```
父级不在 search 结果里 → 孤儿
```

于是任何**直接挂在书签栏下**的书签或文件夹，父级都不在结果集里，全部被误判。

## 修法

改成以**书签树本身**为判据：

```
父级在树里存在 → 正常
父级在树里也不存在 → 真孤儿
```

树是权威结构；`search` 只是用来找"库里存在、但树里够不着"的节点。

## 验证

- 单元：T109 三条 —— 直接挂书签栏的不算孤儿；真正的孤儿仍能检出；没传全量列表时不猜。
- 真机：造两个直接挂在书签栏下的书签，健康检查**不再报孤儿**（实测 `是否报孤儿: false`）。
- 证伪：把判据改回旧版本 → 「直接挂在书签栏下不算孤儿」立刻转红。

## 你该做什么

升级后打开设置页看健康检查——如果之前那条"找不到父文件夹"其实是误报，它现在会消失。

**如果它还在**，那才是真的孤儿数据（树里确实够不着），这时它的提示是准确的：
这类数据只能你自己确认后处理，MarkAI 不会替你删书签。
