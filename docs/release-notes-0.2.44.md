# v0.2.44 — 删掉一条永远不会触发的「检测」

## 问题

0.2.37 的健康检查里有一条：

> **后台异常退出 N 次**

它读的是 `markai.runtime.crash`。但**整个项目里没有任何地方写入这个 key**。

所以这条检测永远显示 0、永远不触发。界面上看起来像个真的监控，实际是死代码——
而我在 0.2.37 的说明里还声称它「能检测后台崩溃」。

这属于我不能接受的那类东西：**看起来在工作，其实没有**。

## 为什么删而不是补

补的话，MV3 的 service worker 有一个根本限制：没有可靠的"正常退出"信号。
`onSuspend` 是 best-effort，不保证触发；空闲回收本来也是正常行为，不是崩溃。

真要做准，就得把"空闲回收"和"真的崩了"区分开——做不到就会变成
「明明没事却报后台崩了 3 次」，比没有更糟。

所以直接删掉：**检测不到的事，不要装作能检测**。

## 顺便说明：真正的中断恢复是有的

你可能会问，那"上一轮被中断"到底有没有兜底？

有，而且和这条假检测无关：`recoverInterruptedTransaction()` 会在 **SW 每次启动时**
把上次没写完的撤销事务提升成一个可撤销点，并在整理记录里写上
「上一轮被中断，已把当时已完成的改动保留为可撤销记录」。

这条链路是真的，有单测覆盖。它的依据是 `markai.undo.pending` 这个**确实被写入**的快照，
不是凭空猜的计数器。

## 新增守卫

加了一条自动化守卫，专门防这类问题复发：

> health 模块读取的每个 `markai.*` key，都必须在 health 目录之外**真的被写过**。

扫源码实现，不是靠人工检查。证伪时把 `markai.runtime.crash` 加回去，守卫立刻报：

```
这些 key 在 health 之外没有任何写入方，对应的检测永远不会触发：["markai.runtime.crash"]
```
