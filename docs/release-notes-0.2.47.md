# v0.2.47 — 让测试替身说实话（第二批）

上一版发现 mock 把 `bookmarks.create` 的默认父级写反了（Chrome 是「其他书签」，
mock 写成了「书签栏」），一个真 bug 因此藏了很久。

这一版把同类问题继续扫下去，对着**真实 Chrome 实测**校准替身。

## 1. `bookmarks.move` 缺越界校验

实测（headless，真实 Chrome）：

```
同父、[a,b,c,d]：
  move(a → index 4)  → [b,c,d,a]   ✔ index == 子项数，合法
  move(a → index 5)  → THROW: Index out of bounds.
跨父、目标 1 个子项：
  move(x → index 1)  → ✔
  move(x → index 3)  → THROW
```

结论：**上限 = 目标文件夹当前的子项数（含被移动的那个自己）**，不是减一。

替身原先完全没有这个校验，`index: 99` 会静默成功——"落点算错"这类 bug
在测试里永远看不出来。现在补上了，并且用 T112 把实测边界钉死。

顺带确认：**生产代码没有踩这个坑**（补上校验后 737 项旧测试全绿）。

## 2. 一条"看起来在测、其实没测"的断言

T111 里那条「子串命中不等于重复」，我写成先存 `.../page` 再存 `.../page2` ——
搜 `page2` 根本不会命中 `page`，等于什么都没验证。

改成反过来：先存 `.../page2`，再存 `.../page`。这样 `search('.../page')`
会同时命中两个（子串匹配），只有 `existing.some(n => n.url === url)`
这一步才能把它们区分开。

并且加了一条**前提断言**：先确认 `search` 真的产生了子串命中，
否则这条测试自动失去意义——不让它在"前提不成立"的情况下绿着。

证伪：把去重逻辑改成 `existing.length > 0`（有命中就算重复）→ 立刻转红。

## 为什么这件事值得做

测试替身不忠实，比没有测试更危险：它给的是**虚假的安全感**。

一个写得像真的、其实行为相反的 mock，会让错误的实现看起来完全正确，
而且这种错误会一直通过 CI、一直发版，直到某个用户碰上。
