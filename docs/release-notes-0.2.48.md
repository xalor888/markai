# v0.2.48 — 「重新生成」可能让你的书签变两份

## 问题

`retryLast()` 的做法是：**删掉最后一条用户消息之后的全部消息，再把同一句话重发一遍**。

它默认「那一轮什么都没发生」。但只要 Agent 已经调用过写类工具，这个假设就是错的。

典型序列：

```
你：  帮我建个书签
Agent：（调用了 create_bookmark，书签已创建）
Agent：（最后一轮没有返回文字）

界面：「Agent 未返回内容，可点击 ↻ 重新生成」
```

这时候书签**已经建好了**。你点 ↻，会重发「帮我建个书签」——再建一个。

**你看到的是「重试一次」，实际是「再做一遍」。**

而且那条带工具记录的消息会被删掉，你再也看不到"其实已经执行过了"。

## 影响面

- `create_bookmark` / `copy_bookmark`：会造出**重复书签**
- `move_*`：移动本身幂等，看不出问题（所以更难察觉）
- `propose_deletions`：会重复生成提议

## 修法

新增 `src/lib/chat/retry-safety.ts`，判断这一轮有没有**成功执行过的写类操作**：

- 有 → 不再提供「重新生成」按钮，空回复文案改成
  「（Agent 没有写回复，但这一轮已经执行了 N 个改动。需要继续请直接说下一句；要退回可点「撤销」。）」
- 没有（纯对话 / 只读工具 / 写操作失败）→ 一切照旧

两道闸门：

1. **UI 层**：不提供入口
2. **store 层**：`retryLast()` 自己再拦一次，防止绕过

写类工具**失败**不算改动——什么都没落地，重试是安全的，这里刻意不拦。

## 测试过程中我自己犯的两个错

**第一个**：控制组断言写的是「重试后消息长度应为 1」，但 `send()` 会同步补一条 assistant 占位，
所以「被拦下(2 条)」和「允许重试(2 条)」长度一样——**两种情况下我的断言都会通过，等于没测**。

改成检查旧消息 id 还在不在，才真正有区分度。

**第二个**：store 测试一开始把 `conversations` 留空，而 `updateActiveMessages`
找不到 active 会话时会直接拒绝写入。于是「被拦下、消息没动」这条断言
其实是白过的——它不是因为拦截而通过，而是**因为根本没写**。控制组当场暴露了这一点。

## 证伪

去掉 store 层保险 → 立刻转红，并且错误信息直接给出证据：

```
已执行写操作时不该裁掉带工具记录的消息，实际 [u1, 2ee0667c-...]
```

旧的 `a1` 被换成了新消息——这正是"工具会被重跑"的证明。
