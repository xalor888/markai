# v0.2.49 — AI 路径第一次在真实浏览器里被测

这一版没有改产品行为，做的是**测试基础设施**：给 e2e 装了一个本地假 AI 服务。

## 为什么值得单独发一版

到目前为止，所有 AI 相关的东西——流式渲染、中断恢复、空回复处理、
草稿落盘——**只在单元测试里跑过**，一次都没有在真实浏览器里验证。

而这恰恰是你抱怨最多的地方：

> 「我一旦退出，它就变成'模型未返回任何内容，请点击重试重新生成'」

之前修的每一处（后台草稿、30s 优雅期、finalize 前强制 flush）
都只证明"逻辑对"，没证明"打开浏览器真的管用"。

现在 e2e 里起一个 OpenAI 兼容的本地端点，返回真 SSE 流，
于是整条链路能端到端跑了。

## 新增 5 条检查（e2e 43 → 48）

1. **正常流式**：模型分三段返回，三段都得渲染出来
2. **结束后回到可输入状态**（不是一直转圈）
3. **中断前**：第一段到达
4. **杀掉 service worker 后重开**：已收到的内容还在，
   且**不能**出现「未返回内容」字样
5. **流式过程中后台草稿在持续落盘**（页面被直接杀掉时的唯一保底）

实测输出里能看到真实的中断文案：

```
（生成被打断，以上是已收到的部分；可点击 ↻ 重新生成完整回复）
这段会被
```

这正是 0.2.39 修的那句话——**第一次被真实浏览器证明生效**。

## 一个诚实的发现

我最初写的中断测试，把开关打在「后台草稿」上，结果**证伪时它照样绿**。

查下去才发现：那条测试能过，靠的是 **UI 自己的 800ms 落盘 + pagehide flush**，
不是因为后台草稿。也就是说它测的机制和它声称的不一样。

于是补了第 5 条：直接去 `markai.ai.draft` 里看草稿有没有在流式过程中持续写入。
这次证伪真的转红了。

两层兜底覆盖的是不同场景：

| 场景 | 谁兜住 |
|---|---|
| 刷新 / 正常关标签页 | UI 的 800ms 落盘 + pagehide flush |
| 页面被直接杀掉（pagehide 都没跑） | 后台草稿（300ms 一次） |
