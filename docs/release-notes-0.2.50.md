# v0.2.50 — 核心 Agent 循环第一次在浏览器里跑通

## 测的是什么

这是整个产品的主干：

```
你说一句话
  → 模型返回 tool_call
  → 我们执行工具（真的动书签）
  → 把结果回填给模型
  → 模型再回一段文字
```

这条链路串起了 `tools.ts`、撤销记录、UI 渲染三块。以前**一次都没在浏览器里跑过**，
只有单测——任何一处接错都看不出来。

现在用上一版做的本地假 AI 服务，把整条链路端到端跑了一遍：

- 第一轮请求 → 假服务返回 `create_bookmark` 的 tool_call
- 我们执行 → 书签真的被创建
- 第二轮请求（带 tool 结果）→ 假服务返回最终文字
- 界面上出现「已经帮你建好了。」

## 三条断言

1. **整条链路跑通**：最终文字渲染出来
2. **工具真的落到了数据**：`chrome.bookmarks.search(url)` 能找到，标题对得上
   —— 而不是只画了个工具卡片
3. **确实发生了两轮请求**：证明工具结果被回填给了模型

第 2 条是关键的：它区分「界面上看起来执行了」和「真的执行了」。

## 证伪

把 `createBookmark` 改成只返回假结果、不真的创建：

```
FAIL  工具调用真的落到了书签数据 · {"count":0,"title":null}
```

而「整条链路跑通」**仍然是绿的**——这是对的，文字确实还回来了。
两条断言测的是不同的东西，这个对比本身就说明设计是合理的。
