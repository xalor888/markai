# v0.2.53 — 时间线的语义，以及两条"写了等于没写"的断言

## 时间线到底在看什么

入口叫「时间线」，卖点是**按收藏时间看全部书签**。

但它以前没有任何验证：单测测的是纯函数（`flattenBookmarks` 之类），
而"这个入口接的是不是全库"是接线问题，纯函数测不出来。

现在在浏览器里验证：造一条书签栏根级的、一条子文件夹里的，
切到时间线后**两条都必须出现在时间线面板里**——证明它读的是整棵树，不是当前文件夹。

同时验证反向：再点一次能回到文件夹视图。

## 两条被我写废的断言

### 一、在整页里找文字

第一版这么写的：

```js
document.body.innerText.includes('TL-子文件夹书签')
```

问题是——**左侧书签树里也可能出现这个标题**。那样测的是"树里有没有"，
不是"时间线里有没有"，等于没测。

改成先拿到 `[data-testid="timeline-panel"]`（新增），只在它内部找，
并且数一下 `role="listitem"` 的条数：

```
{"root":true,"sub":true,"itemCount":3,"headerLine":"3 条书签"}
```

### 二、用 `||` 把断言写成恒真

第二版验证"能切回文件夹视图"：

```js
leavesTimeline: !t.includes('TL-子文件夹书签') || !!document.querySelector('[data-testid="sort"]')
```

「有排序控件」在**时间线模式下也成立**——两个条件任一为真就通过，
所以这条断言永远绿。

改成必须同时满足：时间线面板消失 **且** 排序控件回来。

## 证伪

两条都做了：

- 让 `flattenBookmarks` 不递归子文件夹 → 「时间线面板里有子文件夹书签」转红
  （顺带还有两条旧检查也转红，说明套件有冗余保护）
- 把切换按钮改成单向（永远停在时间线）→「能回到文件夹视图」转红
