# v0.2.54 — 撤销记录被挤掉时，现在会告诉你

## 问题

撤销记录最多保留 **10 步**。第 11 步进来时，最旧的那一步会被挤掉。

而代码是这样的：

```js
const candidates = [point, ...state.points].slice(0, MAX_UNDO_POINTS);
const trim = trimPointsToBudget(candidates, budgetBytes);
const notice = describeUndoTrim(trim) ?? state.notice;
```

`describeUndoTrim` 只描述**字节预算**溢出。**条数**挤掉的那一步，没有任何提示。

于是：你以为「最近 10 次操作都能撤」，实际到第 11 次就悄悄丢了第 1 次。
等你真要用的时候才发现——而那正是最需要它的时候。

这和之前修的「删除类操作没有撤销点」是同一性质的伤害：**不是不报错就算没事**。

## 修法

把条数丢弃也算进提示：

```
撤销记录最多保留 10 步，更早的 1 步已被丢弃
```

中断恢复那条路径（`recoverInterruptedTransaction`）同样处理，两处口径一致。

## 提示在哪能看到

- 加载时弹一条 toast（即时告知）
- 「撤销历史」面板里常驻显示（要用的时候还看得见）

## 测试

**T114** 两条：

- 连做 12 轮写操作后，提示必须点名「丢弃」且说明上限是多少
- 只有 1 步时**不打扰**（不产生多余提示）

**e2e** 一条：种一条上限提示 + 3 个撤销点，打开「撤销历史」面板，
确认那段话以**常驻横幅**形式出现。

## 过程中我又写错了一次断言

第一版 e2e 只查 `document.body.innerText`。去掉横幅后**依然是绿的**——
因为 `refreshUndo` 在 `noticeAt` 变化时会弹一条 toast，那段文字照样在页面上。

也就是说：我的断言测的是 **toast**，不是它声称的「常驻横幅」。

改成断言 `[data-testid="undo-notice"]` 元素，并打开面板再查。这次证伪才真的转红。

顺带发现：种数据时如果 `points` 留空，「撤销历史」按钮是禁用的
（`disabled={undoHistory.length === 0}`），面板根本打不开。
真实的修剪场景是「点数仍是 10 个 + 一条提示」，种子要按真实场景来。
