# v0.2.55 — 弹窗在你还没读到数据时，就说"没有"

## 问题

弹出窗的「待删除清单」卡片，`pendingCount` 的初值是 `0`。

于是**第一次读存储完成之前**，界面就已经写着：

> 当前没有待确认的删除提议。

这是在还不知道的情况下给出确定结论。

Service worker 睡着时，这次读取要几百毫秒——那几百毫秒里，你在看一句假话。

**读失败时更糟**：`pendingCount` 永远是 0，卡片永远显示"没有提议"。
你以为干干净净，其实什么都没读到。

## 修法

把三种语义分开，并且抽成纯函数（原来是一个四层嵌套三元，没法测）：

| 状态 | 显示 |
|---|---|
| 正在读 | 正在读取待办… |
| 读失败 | 读取失败：看不到待删清单，请重开弹窗或打开完整管理页。 |
| 读到了 | 才轮到"有没有待办" |

## 测试

**T115** 五条，逐条钉住每种状态：

- 读取中只说"正在读"，**不能出现"没有"**
- 读取失败要说"读取失败"，**不能出现"没有待确认"**
- 读到且为空 —— 这时才可以下"没有"的结论
- 读到且有提议 —— 分模式说清会不会自动执行
- 空 + 无需确认 —— 也要说明这个模式

**e2e** 一条：在弹窗页面脚本执行前把 `storage.local.get` 打坏，
确认卡片显示「读取失败」而不是「没有待确认的删除提议」。

## 过程中踩的两个坑

**一、`Page.addScriptToEvaluateOnNewDocument` 需要先 `Page.enable`**

第一次跑 e2e 失败，卡片照旧显示"没有提议"。查下去是注入被**静默忽略**——
不报错、也不生效，注入等于没做。补上 `Page.enable` 才生效。

**二、种数据不贴真实场景**

上一轮（0.2.54）种撤销数据时把 `points` 留空，结果「撤销历史」按钮是禁用的，
面板根本打不开。教训：**种子的形状必须和真实场景一致**，否则测的是别的东西。
