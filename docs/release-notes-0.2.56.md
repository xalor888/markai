# v0.2.56 — 核对快捷键面板的承诺

## 为什么做这个

快捷键面板写着：

> 这些键在书签树和中栏列表里都生效

并列了 20 多条。但 e2e 里**只验证过 `↓` 一个键**——也就是说这份说明从来没被核对过。

说明书和实际不符，比没有说明书更糟：用户照着按，得到的是别的东西。

## 核对了四条（都有明确可观测结果）

| 键 | 承诺 | 实测 |
|---|---|---|
| `/` | 在树或列表内聚焦搜索 | ✅ 焦点落到搜索框 |
| `Ctrl+A` | 全选当前列表 | ✅ 所有行 `aria-selected=true` |
| `空格` | 选中 / 取消当前项 | ✅ 选中数改变 |
| `F2` | 重命名当前项 | ✅ 打开重命名对话框 |

四条全部符合说明。

**证伪**：把 F2 的处理改成空操作 → 「F2 打开重命名」立刻转红。

选这四条是因为它们的结果是**可观测的**（焦点位置、aria 属性、对话框出现），
不像 `Home/End` 那样只能靠滚动位置间接推断。

## 未验证的部分（诚实说明）

剩下十几条没有逐条核对，主要是它们的可观测性较差：

- `Home/End`、`PgUp/PgDn` —— 只能靠滚动位置间接判断
- `Shift+Enter`、`Ctrl+单击` —— 涉及新标签页/多选组合，headless 下难稳定断言
- `右键` —— 原生上下文菜单

它们仍然只靠代码审读。台账里记为部分覆盖，不当作已验证。
