# v0.2.57 — 读不到撤销记录时，面板打不开也重试不了

## 两层问题，叠在一起

撤销记录读失败时（Service worker 刚被回收、消息通道异常），界面本来就是想告诉你：

> 撤销记录读取失败，当前状态未知（这不等于「没有可撤销的操作」）

这句话写得对。但问题是——**你看不到它。**

### 第一层：面板打不开

「撤销历史」按钮的条件是：

```jsx
disabled={undoHistory.length === 0}
```

而读取失败时，撤销列表恰好是 0 条。

于是那个唯一能说明"读取失败、不是没有操作"的面板，**在你最需要它的时候被锁死了**。
你在按钮上只能看到一行 title，永远看不到原因。

### 第二层：打得开也没有重试

就算面板打开了，里面只写「请稍后重试或重新打开面板」——把活推给用户，自己不给按钮。

## 修法

1. 按钮改为 `disabled={length === 0 && !undoUnknown}`：状态未知时**也能打开**，
   并把 title 换成「撤销历史（读取失败，可点开重试）」。
2. 面板里加一个**重试**按钮，点了直接调 `refreshUndo()`，带加载态。

## 验证

e2e 三条（用 `Page.addScriptToEvaluateOnNewDocument` 把 `undo:list` 打坏）：

- 读取失败时「撤销历史」按钮**仍可点开**
- 面板里说清「状态未知 ≠ 没有可撤销的操作」
- 面板里给出**可点的重试**

**证伪做了两次**（分别单独验）：

- 把禁用条件改回 `length === 0` → 三条同时转红（面板根本打不开）
- 只去掉重试按钮 → 「给出可点的重试」单独转红

## 这轮我自己也写错一条断言

第四版断言「通道恢复后按钮应该可点」——错了。

恢复后如果本来就没有撤销点，按钮**本来就该是禁用的**（没东西可撤）。
改成断言「失败状态消失」（title 不再提示读取失败）才是对的。

又一次「我以为在测 A，其实在测 B」——这是七天内第五次。
