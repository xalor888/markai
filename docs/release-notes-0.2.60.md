# v0.2.60 — 一次读失败，可以抹掉你全部聊天记录

## 这个 bug 有多严重

对话存储是**整对象覆盖**写的（`chrome.storage.local.set({ [AI_STORAGE_KEY]: {...} })`）。
写之前会先读一次磁盘，把别处写的内容合并进来。

而那段读的 catch 里写着：

```ts
} catch {
  // 重读失败不阻塞落盘
}
```

**读失败了，照样写。**

于是：内存里是什么，磁盘就被覆盖成什么。如果此刻内存是空的（因为更早的一次加载也失败了），
磁盘上的**整份聊天历史就被删除了**。

## 实测

我用测试构造了这条路径：磁盘上有一条旧会话 → 两次读都失败 → 落盘。

修之前，磁盘从 `["conv-keep-1"]` 变成只剩 `["conv-new"]`：

```
AssertionError: 读失败时把磁盘上的历史覆盖掉了（现只剩 ["conv-new"]）
```

**这是不可逆的。** 聊天记录没有备份、没有回收站。

## 修法

读没读成功是硬条件：

```ts
if (!readsOk) {
  set({ persistError: { message: '读取本地存储失败，本次**没有保存**对话…' } });
  return;   // 不写
}
```

宁可不保存，也不能拿不完整的数据去覆盖。同时给出可见提示——
"这次没保存成功"和"悄悄删掉历史"是完全不同的两件事。

## 测试

**T118** 两条，其中关键的一条断言两件事：

1. 磁盘上的旧会话**还在**（没被覆盖）
2. **同时**有 `persistError` 提示

第 2 条不是凑数：如果把 `_persist` 整个删掉，历史同样"还在"，
但用户会在毫不知情的情况下永远丢保存。**"静默什么都不做"也必须被排除。**

## 证伪

去掉 `if (!readsOk) return`：

```
✘ 写盘前重读失败时，不能拿空内存覆盖掉磁盘上的历史
   读失败时把磁盘上的历史覆盖掉了（现只剩 ["conv-new"]）
```

## 一个我差点交出去的假测试

这条用例我第一版写的是「加载失败后写盘，磁盘历史还在」。

**它永远绿**——因为那条路径上有两层合并兜底，我关掉两层它还是绿。
查下去才发现：那次 `_persist()` 根本没走到写盘，磁盘原样不动，断言自然成立。

也就是说它测的不是"合并有效"，而是"什么都没发生"。

改成能逼出真实写入、且**只有加拦截才能通过**的场景，这条用例才有意义。

> 一个我证伪不了的断言，等于没写。
