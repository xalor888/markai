# v0.2.61 — 同一类盲写，这次会清掉你的 API Key

## 情况

0.2.60 修的是对话存储：读失败之后不能拿内存去覆盖磁盘。

配置存储是同一个毛病，但**后果更直接**：

```ts
async load() {
  try { ... } catch {
    set({ config: DEFAULT_CONFIG });   // 失败 → 内存变成空配置
  }
}

async update(patch) {
  const next = { ...get().config, ...patch };   // ← 用这份"空配置"去合并
  await chrome.storage.local.set({ [KEY]: next });
}
```

加载失败后，内存里是 `DEFAULT_CONFIG`（`apiKey` / `baseUrl` / `model` 全是空）。
此时用户只要改任何一个开关，整份配置就被**默认值覆盖**：

- API Key 没了 → 扩展直接不能用，要重新去申请/粘贴
- Base URL 没了 → 自定义端点丢失
- 模型没了 → 回到默认模型
- 上下文长度没了 → 回到自动

而用户完全不知道发生了什么——他以为自己只是拧了一个开关。

## 修法

保存前先确认真拿得到配置：

```ts
if (!get().loadOk) {
  // 读回磁盘上的真实配置再合并
  // 读不回来就不写，并如实告诉他"这次没有保存"
}
```

`loadOk` 记录"本次会话是否成功读到过配置"，加载失败时保持 `false`。
这样既能自动恢复（读回来后正常保存），也不会在拿不到数据时盲写。

## 测试

**T119** 两条：

1. 加载失败后保存 → 磁盘上的 **API Key / Base URL / 模型 / 上下文长度全部还在**，
   而这次改的字段确实生效
2. 读回也失败 → **根本不写盘**、`ok: false`、并有「本次没有保存」的可见说明

第 2 条里"根本不写盘"是硬断言：`ok:false` 但偷偷写了，同样是数据被覆盖。

**证伪**：去掉 `if (!get().loadOk)` 那段 →

```
✘ 加载失败后保存，磁盘上的 API Key / 模型必须还在
```

## 这是一类，不是两个 bug

| 版本 | 存储 | 被覆盖的东西 |
|---|---|---|
| 0.2.60 | `markai.ai` | 全部聊天记录 |
| 0.2.61 | `markai.config` | API Key / 端点 / 模型 / 删除模式 |

**共同结构**：`load` 失败 → 内存退化成默认值 → 保存时整对象覆盖。

写进台账的规则：**任何"读失败就回退默认值"的 store，保存路径都必须先确认内存是真的。**

还有两个同类存储待查：`markai.undo`（撤销点）与 `markai.organize.log`（整理记录）。
