# v0.2.64 — 「没保存成功」旁边只有一个「知道了」

## 问题

对话存储写失败时，聊天面板会弹出一条红色横幅：

> ⚠ 这段对话**没有保存成功**（当前该键占用约 3.2 MiB）：QUOTA_BYTES quota exceeded。建议清空更早的对话后重试。

右边只有一个按钮：**知道了**。

按下去——提示消失，数据仍然没保存。

也就是说：**你看到过一句话，然后什么都没有了。** 唯一能救这一步的操作，得你自己去想怎么做。

## 修法

给 `persistError` 加一个「重试保存」：

- 点击 → 重新落盘
- 成功 → 横幅消失 + toast「已保存」
- 仍然失败 → toast「仍未保存成功」并保留横幅

「知道了」保留，但只在你看完愿意接受风险时按。

## 验证

e2e 四条（用 `addScriptToEvaluateOnNewDocument` 让 `markai.ai` 的写入失败）：

1. 出现「没有保存成功」提示
2. **旁边有可点的「重试保存」**
3. 按钮可点击
4. 恢复写入后点重试 → 提示**真的消失**

第 4 条是关键：它区分「按钮画出来了」和「按下去真的把数据存进去了」。

**证伪**：去掉重试按钮 → 后三条同时转红。

## 顺带：一个我原本以为是问题的地方，量完发现不是

我怀疑流式对话期间每 800ms 整份落盘会造成写入压力，于是插桩量了一次
（300 条历史的会话 + 20 段流式回复）：

```
写入次数 7 次 · 总计 135,725 字节 · 单次最大 21,108 字节 · 平均 19,389 字节
```

**一次对话约 136 KB**，对 `chrome.storage.local` 完全不构成压力。不需要优化。

记下来是因为：如果我凭直觉去"优化"它，改出来的东西既无用又可能引入新 bug。
