# v0.2.67 — 模型不知道今天几号

## 问题

工具回填的书签长这样：

```json
{ "title": "…", "dateAdded": 1667443200000, "dateLastUsed": 1698979200000 }
```

原始毫秒时间戳。而系统提示词里**没有任何"今天是什么时候"的信息**。

于是模型要判断「超过 2 年没访问的过时内容」时，只能拿**自己的训练截止日**当"今天"。

它会算错，而且**错得很自信**——不会说"我不确定现在是哪年"，会直接给你一批
它认为是"两年以前"的书签。

「智能扫描清理」这条快捷指令里就写着这类要求，所以这不是假设问题。

## 修法

每次请求都把当前时间拼进系统提示：

```
## 当前时间
现在是 2026-11-02 13:45（Asia/Shanghai，UTC+08:00），今天是 2026-11-02。
工具返回的 dateAdded / dateLastUsed 是 Unix 毫秒时间戳。判断「多久以前」「是否超过 N 年」
「最近/上周」时，一律以上面这个当前时间为基准换算，不要用你的训练数据里的日期。
```

几个细节：

- **每次请求重新生成**，不是模块级常量——侧边栏可能开一整天，跨过午夜后"今天"要跟着变
- 用 `Intl.DateTimeFormat` 按时区算，不是硬编码 `+08:00`
- 时区不可用时退回本地时间，不会崩

成本约 **178 个字符**（实测系统消息 1781 → 1959）。

## 验证

**T123 四条**（纯函数）：

- 含明确的"今天"日期与时刻
- 指明时间戳单位与换算基准，并明确禁止用训练数据当今天
- 跨时区给出正确日期（`2026-11-02T23:30Z` 在洛杉矶应是 11-02，不是 03）
- 时区不可用时不崩

**e2e 一条**：假 AI 服务捕获真实请求体，断言**系统消息里确实带今天的日期**。
这条验证的是"真的发给了模型"，而不是"函数返回值对"。

**证伪**：
- 去掉注入 → e2e 转红
- 去掉日期 → T123 转红

## 一个自我纠正

第一次证伪 T123 时，我的替换脚本把 `现在是 ` 一起删掉了，导致第二步替换**根本没匹配上**——
代码没变，测试当然还是绿的。

我差点把"绿"当成"断言不灵敏"。核对源码才发现是证伪脚本自己的错。

> 证伪失败时，先怀疑证伪脚本，再怀疑断言。
