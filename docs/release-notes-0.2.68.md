# v0.2.68 — 健康检查里那个"点了没事干"的按钮

## 问题

健康检查报「AI 服务还没配完 · 缺少：API Key」，旁边给了一个按钮：

> 🔧 填入该服务商的默认值

但**填默认值补不了 API Key**——Key 必须你自己去服务商后台拿。

点下去的结果是弹一句「没有可以自动填的字段（Base URL 与模型都已填好），请检查 API Key」。
提示是诚实的，但按钮本身在骗人：它看起来能解决问题。

更糟的是它还被计进「N 个可一键修复」——**健康分看起来有救，实际没有**。

## 修法

只有**确实有字段可补**（Base URL 或模型缺失）时才给这个按钮；只缺 Key 时不给，
只保留那句「到服务商后台复制一个 Key 填进来」。

判断逻辑：

```ts
...(missing.some((m) => m !== 'API Key')
  ? { fix: { action: 'config.fill-defaults', label: '填入该服务商的默认值' } }
  : {}),
```

## 验证

**T124 四条**：

- 只缺 Key → **不给按钮**，但要有明确的手动提示
- 缺 Base URL / 模型 → 给按钮（补得了）
- 三者都缺 → 也给按钮
- 可一键修复的计数不再把"补不了"的问题算进去

**证伪**：改回无条件给按钮 → 断言立即转红：

```
只缺 Key 时不该给 fix：{"action":"config.fill-defaults","label":"填入该服务商的默认值"}
```

## 连带修好一条 vacuous 的 e2e

`一键修复不改动任何书签` 这条用例，之前是**靠这个假按钮撑着**的——
它需要页面上存在「修复全部」，而当时那个按钮恰好因为"缺 Key"而出现。

去掉假按钮后这条 e2e 直接失败（`clicked: false`）。说明它一直在依赖一个
**点了没用**的按钮来证明"点了不会动书签"。

现在改成自己种一个**真的可修**的问题（写坏的自定义请求头）再点，实测
`{"clicked":true,"before":2,"after":2}`——真的点了，书签真的没动。

> 一个靠错误行为撑着的测试，会在错误被修掉的瞬间暴露。
