# v0.2.72 — 现在真的能把书签导出成文件了

## 为什么做这个

你说「帮我把书签备份一下」的时候，这个插件**给不出一个文件**。

- AI 的 `export_bookmarks` 只把清单**返回给模型分析**，不产文件（工具描述也是这么写的，诚实）
- UI 里只有「导出对话」「导出整理记录」
- 设置页的数据管理只有「清空」

于是"备份书签"这件事只能去浏览器自带的书签管理器做。

## 做了什么

设置页 → 数据管理 → **书签导出**：

| 按钮 | 格式 | 用途 |
|---|---|---|
| 书签 HTML | Netscape 书签文件 | Chrome / Edge / Firefox / Safari 都能直接导入 |
| JSON | 完整结构 + ISO 时间戳 | 程序处理 / 自己写脚本 |

按钮旁边会先读真实书签数：「将导出 N 条书签 · M 个文件夹」。

## 为什么格式用纯函数实现

导出一份**格式错的文件**比不导出更糟——你会以为备份好了，等真要恢复时才发现导入不了。

所以格式生成是纯函数（`toNetscapeHtml` / `toJsonExport` / `countTree`），
全部靠单测钉死，不需要开浏览器：

- HTML 转义：`& < > "` 都要转，**URL 里的 `&` 也要转**（否则链接会断）
- 时间戳按**秒**输出（Netscape 规范用秒，书签 API 给的是毫秒）
- **空文件夹也要输出**，且 `DL` 必须立刻闭合——否则导入后层级就变了
- 虚拟根不输出，只输出它的子节点（书签栏 / 其他书签）
- JSON 不导出 `parentId` 这种内部引用

## 验证

**T127 九条**（纯函数）。

**e2e 两条**：在真浏览器里点按钮，拦截 `a.click()`，
核对真的产生了下载、**文件名与 MIME 都对**：

```
[{"size":671,"type":"text/html;charset=utf-8"},
 {"name":"MarkAI-书签-2026-11-02.html","href":"blob:chrome-extensio…"}]
```

**证伪**：把 `a.click()` 去掉 → 两条同时转红。

## 过程中的两个小坑

1. 我给 e2e 断言的是一条记录里同时有 `name` 和 `type`——
   但 `createObjectURL` 和 `a.click()` 是两条不同记录。改成分别核对。
2. 原来用固定 `sleep(500)` 等下载，出现过一次偶发假失败。
   改成 `waitFor` 下载记录出现，之后连跑 **7 次全绿**。
