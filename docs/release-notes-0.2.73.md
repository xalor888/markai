# v0.2.73 — 别再说"已为你导出"了

## 问题

上一版刚加了「书签导出」。但在这之前，用户说「把我的书签导出备份」时会发生什么？

所有工具都只把数据**读给模型分析**，磁盘上一个字节都不会多。而模型没有任何依据知道
"我做不到"——它很可能顺口回一句：

> 好的，已为你导出书签。

你去磁盘上找，什么都没有。

**不是它坏，是没人告诉它边界在哪。**

## 修法

在系统提示里加一条（每次请求都会带上）：

> **你产不出文件，也不要声称产出了。** 所有工具只把数据读给你分析，不会在用户的磁盘上
> 生成任何文件。用户要求「导出 / 备份 / 保存成文件」时：如实说明你只能读分析，
> 让他们去 **设置 → 数据管理 → 书签导出**（有「书签 HTML」与「JSON」两种，
> HTML 可再导入任意浏览器）。**不要**为了让用户满意就说"已为你导出"或编造一个文件名。

注意后半句是刚需：上一版刚做了这个功能，**模型得知道去哪儿指**。

## 验证

**T128 三条**：

1. 明确说明产不出文件、不要声称导出
2. 把用户指到**真实存在的入口**（书签导出 / HTML / JSON）
3. 口径一致：`export_bookmarks` 不能被描述成"导出文件"

第 3 条防的是"一边说产不出文件，一边把工具描述写成导出文件"这种自相矛盾。

**e2e 一条**：假 AI 服务捕获真实请求，断言**系统消息里**确实有这句。
（这验证的是"真的发给了模型"，而不是"常量写对了"。）

**证伪**：去掉这条 → 单测与 e2e 都转红。

## 又一个「改完忘 build」

第一版 e2e 跑出来是红的。查下去不是断言错——是**我改完 `prompts.ts` 没重新 `build`**，
页面还在跑旧包。`npm run build` 之后立刻绿。

这是本轮第三次同类失误（前两次也是这个坑）。记在这里提醒自己：

> 改了源码后，e2e 之前必须 `npm run build`。否则你看到的红/绿都是旧代码的。
