# v0.2.74 — 每次打开都闪一下别的颜色

## 问题

主题存的是 `chrome.storage.local`——**只能异步读**。

而四个入口都在模块求值阶段（React 渲染之前）做了一次"同步预应用"，
判断依据只有一条：**系统偏好**。

于是：**系统是深色、但你在设置里选了浅色**的人，每次打开侧边栏/设置页/弹窗，
都会先看到一帧深色，然后才被异步的 `load()` 纠正成浅色。

反过来也一样：系统浅色、你选了深色 → 先白一下再变暗。

不是大问题，但**每次打开都有**，而且是你第一眼看到的东西。

## 修法

把用户的选择**镜像一份到 `localStorage`**（同步可读），首帧就能拿到：

```
首帧优先级：用户显式选过 > 系统偏好
```

- `shouldStartDark(saved, systemDark)` 做成纯函数——脏值不猜，当成"没选过"跟随系统
- `preapplyTheme()` 在模块求值阶段调用，四个入口统一走它
- `setTheme` / `load` 时同步写镜像（写不进去不影响功能，只是首帧退回系统偏好）

## 验证

**T129 三条**：显式选择优先 / 没选过跟随系统 / **脏值不猜**。

**e2e 两条，双向**：

| 场景 | 期望 |
|---|---|
| 系统深色 + 用户选浅色 | 首帧 `class=""` |
| 系统浅色 + 用户选深色 | 首帧 `class="dark"` |

判据卡在 `DOMContentLoaded` 这一刻记录 `<html>` 的 class——
那时模块脚本已执行完（同步应用就在这里），而 `load()` 的 storage 读取还没回来。
**不卡这个时刻，就测不出首帧。**

**证伪**：把 `shouldStartDark(...)` 换回只看系统偏好 → 两条同时转红。

## 过程中的一次误判

我一开始以为问题是"深色用户闪白"，加了个模块级的 `applyTheme('system')`，
证伪时**居然不红**——查下去发现入口早就有按系统偏好的预应用，我的改动是多余的，
而且真正常发生的闪白是**反方向**的（选了浅色的人闪深色）。

> 证伪不红的时候，要回去改证伪，也要回头核对"我以为的问题是不是真问题"。
