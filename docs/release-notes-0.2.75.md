# v0.2.75 — 同一个规则，不该写两遍

## 问题

0.2.70 我把弹窗的「收藏当前页」放宽到了 `file://`（Chrome 自己也允许收藏本地文件）。

但**新建书签对话框的预填**里还写着一份独立的判断：

```ts
if (u && /^https?:\/\//i.test(u)) { ...预填标题和地址... }
```

同样是"拿当前页预填"，本地文件用户在**弹窗**里能拿到、在**新建书签对话框**里拿不到。

同一个规则写了两遍，改一处漏一处——这和 0.2.66 那次「配置有两条写入路径」是同一类问题。

## 修法

抽成纯函数 `prefillFromTab(tab)`，判据统一走 `isSavableUrl`：

```ts
export function prefillFromTab(tab) {
  const url = tab?.url;
  if (!url || !isSavableUrl(url)) return null;
  return { title: tab?.title?.trim() || url, url };
}
```

顺带修了一个小毛病：标题只有空白时原来会预填一个空标题，现在退回用 URL。

## 验证

**T130 五条**：

- 本地文件页也能预填（与收藏入口一致）
- 没有标题时用 URL 兜底
- **标题只有空白时也退回 URL**
- 浏览器自身页面不预填（同一判据）
- 没有活动标签页时返回 null（不崩、不预填半截）

**证伪**：把 `prefillFromTab` 里的判据换回 `/^https?:\/\//` →

```
✘ 本地文件页也能预填（与收藏入口一致）
```
