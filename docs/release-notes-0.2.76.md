# v0.2.76 — 冷启动实测：不用优化，但数字要留在仓库里

## 结论先说

冷启动**不是瓶颈**，不需要优化。

但台账里"冷启动预算"这一项挂了很久一直没有实测——**凭感觉说"够快"不算数**。
所以这一版把测量做成了仓库里的脚本，数字可复现。

## 实测数字

`node scripts/measure-coldstart.mjs <书签数> <次数>`

| 库大小 | topbar | 输入框 | 列表出行 |
|---|---|---|---|
| 450 条 | 84ms | 71ms | **93ms** |
| 1800 条 | 135ms | 91ms | **144ms** |

三个阶段按用户能感知的顺序：顶栏出现 → 对话输入框能打字 → 中栏渲染出第一行书签。

**缩放基本线性**（4 倍书签 → 约 1.5 倍耗时），且都远低于"用户能感觉到卡"的量级（>1s）。

## 为什么这个脚本值得进仓库

1. **性能说法必须带数字**——这是本项目的硬规矩；
2. 以后再有人问"启动慢不慢"，跑一条命令就有答案，不用重新搭测量环境；
3. 它记录的是**用户能感知的三个节点**，不是内部指标。

## 顺带修了脚本自己的一个坑

第一版跑完不退出——CDP 的 WebSocket 会保活事件循环，
脚本打印完结果就挂在那里。补了 `process.exit(0)` 才正常结束。
