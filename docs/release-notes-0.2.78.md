# v0.2.78 — 设置页某一节崩掉，不该带走整页

## 问题

项目里早就有 `ErrorBoundary`，但**只包了两个地方**：设置页的「健康检查」和工作区的「书签树」。

其余五节——AI 服务 / 上下文与预算 / Agent 行为 / 外观 / 数据管理——**什么都没有**。

React 19 里任何子组件抛错都会卸掉整棵树。所以只要其中一节出问题，你看到的是
**一页纯白的设置页**：没有报错、没有重试、不知道哪儿坏了，只能重开。

而这些节全都在读 `chrome.storage`、解析用户填过的自定义请求头、渲染记忆列表——
都是"一次意外丢字段就够抛错"的地方。

## 修法

给设置页六节各自包上 `ErrorBoundary`：

```
健康检查 / AI 服务 / 上下文与预算 / Agent 行为 / 外观 / 数据管理
```

任一节崩掉 → 只那一节变成"出了点问题 + 具体错误 + 重试"，**其余节照常可用**。

顺带给 `ErrorBoundary` 加了一个 `data-error-boundary` 属性——正常渲染时不产生任何盒子
（仍然是 `display: contents`），只是让"这一节有没有被包住"变成可断言的。

## 验证

e2e 两条：

1. **六节各自都有错误边界**——直接数 DOM 里的 `[data-error-boundary]`，
   实测 `{"have":["MarkAI 设置","健康检查","AI 服务","上下文与预算","Agent 行为","外观","数据管理"],"missing":[]}`
2. 页面正常渲染（不是白屏、没掉进边界）

**证伪**：把「数据管理」那节的边界去掉 → 第 1 条立刻转红。

> 值得说明：原本我想写"注入一个崩溃，验证其余节还在"，但从外部逼一个 React 子组件
> 抛错不可靠（找不到稳定的注入点），最后退到**结构断言**。
> 结构断言能证明"有边界"，不能证明"边界真的接住了异常"——这一点我在测试名里写清了。
