# v0.2.79 — 同一个动作，只能有一个名字

## 问题

同一个动作在多个入口出现：侧边栏右键、中栏工具栏、空状态提示、快捷键说明、扩展图标右键。

以前每处各写一遍字符串，于是出现了：

| 入口 | 文案 |
|---|---|
| 中栏工具栏 | 让 MarkAI 整理**选中项** |
| 侧边栏右键 | 让 MarkAI 整理**所选**（N） |

用户在两处看到同一个动作的两个名字，**会以为是两个功能**。

这和 0.2.66（配置有两条写入路径）、0.2.75（URL 判据写了两遍）是同一类问题：
**规则/文案只有一份，却散落在多处。**

## 修法

新增 `src/lib/ui/labels.ts`——界面动作文案的**唯一来源**：

```ts
export const ORGANIZE_LABEL = {
  folder: '让 MarkAI 整理',
  selection: (n: number) => `让 MarkAI 整理所选（${n}）`,
  all: '让 MarkAI 整理全部书签',
  analyze: '让 MarkAI 分析',
};
```

工具栏与树右键都改成引用它。以后要改文案，改一处。

## 验证

**T131 三条**：

- 选中项的名字只有一种写法（且断言里**不能再出现「选中项」**）
- 各个 scope 的名字互不串味（`Set` 去重后数量不变）
- **提示文案里引用的就是按钮上的名字**——不是各写一遍，写死后迟早对不上

**e2e 一条**：整页文本里不能再出现旧叫法「整理选中项」。

**证伪**：把 `selection` 改回「整理选中项」→ T131 立刻转红。
