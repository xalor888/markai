# v0.2.84 — 提示词在自相矛盾，而且没人看得出来

## 一个真缺陷

同一份系统提示里，隔着几行：

- **第 4 条**：「**不要按域名新建文件夹**（例如「自动整理/github.com」这种）——用户明确表示不用这种分类法」
- **第 10 条**：「`auto_categorize` 一次完成整文件夹的自动分类（**按域名聚类，内部批量建文件夹并移动**）」

而 `autoCategorize` 的实现里，建的文件夹名就是域名：

```ts
const folder = await jCreate({ parentId: pid, title: g.domain });
```

模型同时读到这两条，要么拒绝调用用户明确要用的工具，要么违反用户明确表示过的偏好。

**没有任何测试会发现这件事**——两句话都是"合法文案"。

## 修法

1. 工具描述补上前提：**只有用户明确要求"按域名/按网站分类"时才可调用**；用户只说"整理一下"时不要用它
2. 第 10 条的提及同样标注前提

## 静态守卫（台账里挂着的那一项）

新增 `src/lib/guards/removed-behavior.ts`，两条规则：

**规则 1**：`title: x.domain` 这种**形状**的调用只能出现在受控位置（文件或所在函数名带 domain/categorize）。判据是形状不是字符串——换个变量名照样认得出。

**规则 2**：提示词不能同时对同一件事既禁止又允许。

## 三个值得记的坑

### 1. 守卫查错了对象

规则 2 最初查的是**源码文件**。但源码里的注释**不会发给模型**——我加的解释注释让守卫永远绿，
而用户看到的矛盾早就消除了（或者说，矛盾在不在跟注释无关）。

改成查**运行时的 `SYSTEM_PROMPT` 与 `TOOL_DEFINITIONS`**。

### 2. 证伪脚本静默未命中（第三次）

源码里用的是弯引号「」，我在 Python 里写了直引号 `"` —— 替换没匹配上，
**代码没变，测试当然还是绿的**。我差点又得出"守卫没灵敏度"的结论。

这正是本 session 早先记过的坑，这次又栽了一次。

### 3. `git checkout` 回退了我未提交的修改

证伪后我用 `git checkout src/lib/ai/prompts.ts` 恢复，
结果把本轮**还没提交的真正修复**一起回退了。重做了一遍。

> **未提交的修改不要用 `git checkout` 恢复**——用 `cp` 备份/恢复。

## 验证

T133 三条，其中第三条是**守卫自己的灵敏度**（防止它永远返回空）：

- 造一个显然违规的输入，必须能认出来
- 造一个显然矛盾的提示词，必须能认出来
- 正确形状不应误报

两条规则分别证伪过：致盲规则 1 → 红；致盲规则 2 的工具描述分支 → 红。
