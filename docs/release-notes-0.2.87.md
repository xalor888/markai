# v0.2.87 — 删除的安全网，以前没验过兜不兜得住

## 缺口

删除是整个产品里**唯一不可逆**的动作。整套安全设计都建立在它上面：

> AI 只能提议 → 用户显式点击 → 才真删

e2e 验到「用户点了之后，书签真的被删掉」就停了。

**但没验过：删完之后能不能撤回来。**

而「不可逆」这三个字，正是靠撤销兜底的。如果删完撤不回来，前面整套设计就白做了——
用户点错一次就永久失去那条书签。

## 补上了

```
PASS  删除也落成了撤销点（不可逆动作有安全网）        {"delPoint":true}
PASS  删掉的书签能通过撤销找回来（安全网真的兜得住）
       {"back":true,"backInfo":{"count":1,"title":"E2E 待删书签","newId":"18","oldId":"17"}}
```

## 过程中我又写错了一个判据

第一版按**旧 id** 查书签回没回来，永远是 false。

原因：撤销是用删除时抓的**子树快照重建**，Chrome 会给新节点发**新 id**
（实测 `oldId: "17"` → `newId: "18"`）。

按旧 id 查，会把「撤回来了」误判成「没撤回来」。

改成按 **URL** 查——那才是用户视角：「我那条书签回来了没有」。

两条新检查。**证伪**：把 `captureForDelete` 换成不抓快照 → 两条同时转红。
