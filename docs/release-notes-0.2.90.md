# v0.2.90 — 快捷键说明里列的键，第一次真按了一遍

## 缺口

快捷键对话框承诺了：

```
↑ ↓  上下移动高亮        ← →  折叠/展开      Home End  首项/末项
PgUp PgDn  整页翻动      Enter  打开当前项    空格  选中/取消
Shift+↑↓  范围选择        Ctrl+A  全选        F2  重命名
Delete  删除              Ctrl+C  复制网址
```

e2e 里**一个都没真按过**（只有 Ctrl+K / Esc / 方向键在树里）。

用户照着说明按，哪个坏了根本不知道——**说明文档就成了谎言**。

## 补了什么

| 键 | 验的是 |
|---|---|
| `End` | 高亮跳到最后一行 |
| `Home` | 高亮跳回第一行 |
| `Enter` | 进入高亮的文件夹（**列表内容随之变化**） |
| `Shift+↓` | 扩选范围（普通方向键只移高亮，**Shift 才真选中**） |
| `Delete` | 弹出删除确认（**不绕过确认直接删**） |

```
PASS  按 Home 高亮跳回第一行                         {"activeIdx":0}

```

## 为可观测性加了一个属性

高亮行原来只靠 `bg-muted` 类名，和选中态分不开。给行加了 `data-active`。

（和之前给命令面板加 `data-kind`、给消息加 `data-failed` 一样——
**让"状态"可断言，而不是让测试去猜类名**。）

## 过程中踩的坑

1. **点「全部」会把文件夹选择清掉** → 列表退回「还没有选择文件夹」，后面键盘全部落空。
   改成重新选「书签栏」。
2. **用文案匹配数选中项不可靠** → 改成数 `aria-selected="true"` 的行数。
3. **视图里只有一行时 End/Home 无从区分** → 段落开头自己种几条书签。

## 验证

**证伪**：去掉 Shift 范围选择 → 该条立刻转红。
