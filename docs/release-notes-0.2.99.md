# v0.2.99 — 快捷键速查表那句"不写应该支持的键"，现在有人守了

## 起点

快捷键速查表的注释写着：

> 这里只列**代码里真实绑定过**的键，不写"应该支持"的键，避免帮助本身在撒谎。

**但没有任何东西守着这句话。**

而这类缺口是真实发生过的：空态提示从 0.2.x 起就写着「或按 Ctrl+D 把当前页面收藏进来」，
全库却找不到任何 `key === 'd'` 的分支——用户照着提示按下去什么都没发生（0.2.98 才补上）。

一条没人守的承诺，迟早会再骗人一次。

## 做了什么

新增 `src/lib/guards/shortcut-contract.ts`：

```
说明里列的键  ──→  必须能在处理器源码里找到对应 case / key 判断
```

- 从 `shortcuts-dialog.tsx` 导出 `SHORTCUT_GROUPS`（说明的唯一来源）
- 从四个处理器源码抽真实接住的键
- 差集为空才算通过

**跳过注释行**——注释里出现的键不算接住（`// Ctrl+C：复制…` 这种说明文字到不了运行时）。

**不苛求不对应键盘事件的条目**：`Ctrl+单击`（鼠标）、`右键`（contextmenu）、
`Ctrl+Shift+M`（Chrome commands API，manifest 层）、`Esc`（Dialog 组件统一处理）。

## 过程中两次是守卫自己的局限

1. 说明写 `PgUp/PgDn`，而 `KeyboardEvent.key` 的标准值是 `PageUp/PageDown` → 加别名
2. workspace 的 ⌘K 写成 `e.key.toLowerCase() === 'k'`，原正则匹配不到 → 扩展形态

两次都**先怀疑自己的判据**，确认不是产品缺口才改守卫。

## 验证

**证伪**：往速查表里加一个不存在的 `Ctrl+Z` → 守卫立刻报出来：

```
AssertionError: 快捷键速查表列了但处理器里找不到的键：
[{"keys":["Ctrl","Z"],"desc":"撤销上一步（承诺了但没实现）"}]
```
