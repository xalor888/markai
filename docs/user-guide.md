# MarkAI 使用指南

> 这份文件回答「怎么用」，不是「有什么功能」。功能清单看 README，改动细节看 `docs/`。

---

## 一、第一次用（三步）

1. **配好 AI（可选）**：点顶栏齿轮 → 填 Base URL、模型名、API Key → 点「测试连接」。
   不配也能用——自动整理会退回本地规则与域名归类，只是判断没那么准。
2. **收藏一个网页**（Ctrl+D，或点顶栏的书签图标）。
   **约 0.15 秒后**它会自己归位，右上角会弹一条提示告诉你去了哪里。
3. **想知道它做了什么**：点顶栏的「整理」按钮（带小圆点表示有新记录）。

---

## 一·1 第一次打开会看到什么

中栏底部有一条**三步提示**（「整理记录在这里」1/3 → 下一步），说的是三件事：
整理记录在哪、补整理连旧书签也能收拾、怎么撤销。看完或点 × 之后不再出现。

树的文件夹后面有数字（书签栏 `1`、设计资料 `4`）——那是**直接子项数**，
扫一眼就知道哪里东西多，不用逐个点进去。

---

## 二、收藏之后会发生什么

MarkAI 按这个顺序判断，能自己搞定就不打扰模型：

| 顺序 | 依据 | 花不花模型调用 |
| --- | --- | --- |
| 1 | 你已经有一个同品牌的文件夹（如「Radix UI」对应 radix-ui.com） | 不花 |
| 2 | 让模型看标题和域名，挑一个已有文件夹 | 花一次 |
| 3 | 让模型建议一个新文件夹名 | 花一次 |
| 4 | 模型没给出可用结论 → 退回本地规则（名称/类别匹配） | 不花 |
| 5 | 最后兜底：放进「自动整理 / 域名」 | 不花 |

**「判断来源」**那一行会告诉你实际走了哪条：本地规则越多，越快也越省钱。

### 它不会动的东西

- 你已经手动归类过的书签（父级不是根目录的，一律不碰）
- 你手动建好的文件夹结构
- 已经「停用自动整理」的站点

---

## 三、不满意，怎么撤

**一条**：整理记录里点那一行的「↶」。
**全部**：整理记录里点「撤销全部 N 步」——从最新开始连续回退。

撤销之后，**那个站点会自动「停用自动整理」**（下次收藏不再自动搬），
这样你不会陷入「它搬、你撤、它又搬」的循环。想让某个站点重新参与，
在面板底部「已停用自动整理」那一行点站点后面的 ×。

> 「撤销全部」遇到**含删除的操作**会停在那里并告诉你剩几步——删除不能回退是刻意的安全边界。

## 四、整理记录怎么用

| 你想干的事 | 怎么做 |
| --- | --- |
| 看它刚才把书签放哪了 | 打开就有，最近那一条会淡高亮 |
| 只看失败的 | 点「失败 N 条」 |
| 找一条具体的 | 搜索框输标题 / 域名 / 去向 |
| 重试一条失败的 | 那一行的 ↻ |
| 重试所有失败的 | 「重试全部 N」（两条以上才出现） |
| 把以前散落的也收拾一遍 | 「补整理已有书签」→ 开始（有进度和剩余时间，可取消） |
| 留个记录 / 发给别人 | 「导出」→ 生成 Markdown，含统计、判断来源、已停用的站点 |
| 清空历史 | 「清空记录」（会二次确认） |
| 让某个站点重新参与自动整理 | 底部「已停用自动整理」那行点 × |

**补整理只处理散落在根目录的书签**，你手动搭好的分类不会被动——这是刻意的保守。
按钮上方会写明规模（「检测到 9 条散落在根目录的书签」），点之前就知道要处理多少条。
补整理跑到一半关掉面板也没关系：再打开时进度会接回来。

想整理某个具体的文件夹：右键它 →「让 MarkAI 整理」。文件夹超过 100 条时会先说明代价。

## 五、键盘

按 `?` 随时看当前生效的全部快捷键。常用的：

| 键 | 动作 |
| --- | --- |
| `↑` `↓` | 在树 / 列表里移动 |
| `←` `→` | 折叠 / 展开树节点 |
| `Enter` | 打开（文件夹则进入） |
| `Esc` | 清除多选 / 关闭浮层 |
| `Ctrl/Cmd + 点击` | 多选 |
| `Shift + 点击` | 区间多选 |
| `F2` | 重命名 |
| `Delete` | 删除（需确认） |
| `Ctrl/Cmd + A` | 全选 |

## 六、常见问题

**「它把我的书签搬走了，我不知道去哪了」**
→ 整理记录里有每一条的去向，点「↶」可以退回去。

**「某天开始不再自动整理了」**
→ 三个可能：设置页里关掉了、那个站点被停用了（面板底部能看到）、
或者短时间内新增太多被当成批量导入跳过了（这种情况记录里会有一条「批量新增 N 条」的说明）。

**「撤销不了」**
→ 含删除的操作不支持回退；或者你点的不是最新那一步（撤销必须从最新开始，避免把后来的改动一起抹掉）。

**「补整理了 200 条，能一次全退吗」**
→ 每条整理是一个独立的撤销点，最多保留最近 10 个。所以能退最近 10 步。
这是可靠性优先的选择：一次退太多会牵扯「新建文件夹」的递归删除，容易牵连同一批里的其它书签。

**「它在后台跑，会拖慢浏览器吗」**
→ 补整理是逐条的，每批之间有让出；1200 条规模下主线程最长一帧 19ms。
真正的耗时在书签 API 调用（12000 条约 25 秒），不在界面渲染。

## 七、它记录了什么、存在哪

- 整理记录、已停用的站点、撤销点：都在 `chrome.storage.local`，**不上传**
- 只有「让模型判断归属」这一步会把标题和域名发给你配置的服务商
- 关掉设置页的「允许 AI 参与自动整理」后，收藏动作**不会向服务商发送任何网址**
